## 硬边界

仅使用用户 `.env` 中配置的云端 MySQL，目标须为总指挥批准的 `tutor_workspace`。配置白名单先于连接；连接后必须执行 `SELECT DATABASE()` 验证再继续，不匹配立即停止且不输出实际值。禁止创建/删除数据库、切库、清库和修改其他库。用户自行维护凭据和最小权限，不在此记录真实连接值。

迁移、种子、真实API测试使用Node 24原生环境加载；应用使用Nuxt私有运行时配置。多语句执行关闭，业务查询参数化，会话时区设为UTC。只读API池大小5、等待队列20，事务成功commit、失败rollback、连接finally释放；应用关闭结束连接池。

## 显式迁移

```powershell
pnpm db:migrate
```

固定清单：`000_schema_migrations.sql` → `001_students.sql` → `002_contracts.sql`。按版本限制允许创建的表与外键引用，禁止任意SQL输入；每次DDL/登记写入前校验目标库。MySQL 8.0.16+，InnoDB/utf8mb4；成功才登记版本与SHA-256校验和。连接级执行锁防迁移并发，重复执行匹配后跳过。

- `schema_migrations`：版本主键、校验和、应用时间。
- `users`：人员主键、非空姓名、时间；无登录信息，仅演示人员引用。
- `students`：基本信息、可空负责人/性别；FK到users且RESTRICT；年级/状态/性别/姓名CHECK；筛选与负责人索引。不建未来领域表，无删除接口。
- `contracts`：仅S2合同，编号唯一、学生/人员FK、类型字段互斥CHECK、version、科目与学生日期索引。编号不可经API修改。无历史审计/删除。

迁移账号需批准库内CREATE、REFERENCES、SELECT、INSERT及相应函数能力。S1读API只需SELECT；S2运行合同写API另需contracts的INSERT/UPDATE。不要求全局/跨库权限、不自动改账号或授权。

S2开工曾因S1已登记SQL的空行丢失而停止。只读比较确定恢复空行及LF后SHA-256与原台账精确匹配，故只恢复原文件字节；没有改SQL语义、表结构或台账。已新增.gitattributes固定迁移LF格式。今后不得格式化已应用SQL、移除空行或直接改校验和；不匹配须先停止核对。

## 合成演示装载

```powershell
pnpm db:seed
```

要求已登记001迁移且users/students均无数据。一个事务创建1名演示老师、12名合成学生，覆盖5个年级、3种状态、空负责人/性别；联系方式为空，无真实数据、不读取mock JSON。表非空时整次不写入、不覆盖、不补齐。使用装载锁避免两个脚本并发；装载时不要启动其他数据写入流程。

成功后只输出合成人数和供用户手工填写 `DEV_ACTOR_ID` 的演示人员ID，不自动写.env。重复运行安全停止，不输出已有人员数据。未保留初次ID时，由授权维护者在批准库内核对合成人员，不根据真实人员猜测ID。

### S2合同种子与真实测试

`pnpm db:seed:contracts`：仅为已识别S1合成学生01/02追加6条合成合同；需有效且匹配合成人员的服务端DEV_ACTOR_ID。每个目标学生已有任何合同时跳过该学生，不补齐、不覆盖。装载采用事务/执行锁，每条写入前校验DATABASE()，编号随机生成，不依赖mock JSON。

`pnpm test:s2:api`：显式连接批准库和本机API，仅选择S1合成学生。数据库约束与事务失败测试通过rollback撤销未提交插入，不清库；HTTP新增数据已提交，成功结束后仅将本次7条测试合同改成失效状态并保留历史。失败中断时保留已提交数据供核对，不擅自删除；不与其他人工写测试同时运行。S2无删除接口。

## 失败与回退

MySQL DDL隐式提交，无法用事务完整回滚一组建表操作。若第二张表失败，前一张可能保留；脚本检测未登记同名表/部分迁移后停止，**不自动删表、清数据、补写版本或重建**。错误仅给安全提示，不展示驱动异常、SQL参数或配置。

1. 停止再次执行写操作，保留已产生表和记录。
2. 用户/授权维护者先校验当前库，只核对S1/S2已授权四张表的结构、记录和脚本校验和，不输出凭据。
3. 将结构差异和失败步骤（非敏感信息）交总指挥，单独审批可追踪修复；不要手改已应用SQL或伪造版本登记。
4. 应用回退只回退本次代码，保留表与合成数据，不提供破坏性down命令；不把回退后mock页面宣称为真实API结果。

若确需删除S1表/合成数据，须另行明确审批目标、备份和恢复方案，本次未授权且未执行。种子DML失败自动事务回滚；自增ID可能留空洞，属于正常行为。

S2回退：停止合同写入口，回退S2应用与学生合同聚合读取，保留contracts及S1数据，不提供自动破坏性down。若002建表成功但登记失败，停止人工核对；不假装回滚DDL、不删除学生、不重写已有编号。结构修复/删除另行审批。
