## 1. 目标与非目标

### 1.1 目标

让学管师能够在学员管理页新建学生，在学生详情页维护基础档案，并安全地变更学生业务状态；保存后能在列表、详情和首页看到一致结果，同时保护已有合同、学习记录、学习计划和任务分配关系。

### 1.2 已确认范围

本模块只包含：

1. 新增学生。
2. 编辑学生基础档案。
3. 学生状态变更：在读、待分配、已结课。
4. 学员管理页和学生详情页接入入口、loading、成功、失败和冲突反馈。

明确不包含：

- 物理删除、软删除、批量删除、删除后的恢复或解除关联；“已结课→在读”仅是允许的业务状态变更。
- 合同、学习记录、学习计划、任务定义、任务分配的编辑或迁移。
- 登录、角色权限、操作审计、提醒和风险标记。
- 负责人分配、学生导入导出、附件、家长端能力。

现有学生列表与详情的真实查询、合同/记录/计划/任务聚合继续有效。本模块只是增加 students 的受控写入口；已有学生关联数据不得因本模块被删除、清空、解绑或迁移。

## 2. 角色与权限边界

### 2.1 当前无登录阶段

- 页面角色按“内部学管师”设计，但系统尚无登录和真实权限隔离。
- 服务端从当前登录会话构造操作人上下文；浏览器不得传入 `actorId`、`ownerUserId` 或伪造作者。
- 只能在批准的受控开发/测试库使用合成数据，不得公网部署或导入真实学生数据。

### 2.2 未来鉴权迁移边界

未来接入鉴权时，仅替换“请求上下文 → 当前用户 ID”的来源，保留学生数据模型和 `owner_user_id` 外键；跨负责人编辑、变更历史和字段级权限必须由权限/审计模块定义。本模块不预埋绕过权限的特殊分支。

### 3.2 不属于档案表单的字段

科目、到期时间、最近跟进、进行中的学习计划、任务列表及其数量都是 S2–S6 聚合结果。它们由各自服务端查询负责，学生表单不展示编辑控件，写接口拒绝这些字段。负责人同样只读，新增学生不自动分配负责人。

### 3.3 联系方式脱敏

数据库保存 trim 后的原值。列表不查询或返回任何联系方式字段（包括 `guardianPhoneMasked`）；详情及写成功响应只返回 `guardianPhoneMasked`：11 位手机号显示前 3 位和后 4 位，中间 4 位用 `*`；其他格式显示前 2 位和后 2 位，中间全部用 `*`；不足 5 个字符时只显示 `*`。编辑侧栏打开时通过独立 `StudentEditView` 获取明文，且仅限当前无登录的受控合成环境；真实试用前必须由鉴权方案替换该边界。

## 4. 已确认业务规则

### 4.1 同名与可能重复

允许同名、同学校、同班级学生存在，因为兄弟姐妹、同名学生和转学生是合理业务情况；不建立这三个字段的数据库唯一约束。

为降低误建风险，服务端以姓名、学校、班级 trim 后完全相同且三者非空作为“可能重复”条件：

1. 首次创建不带确认标记时，返回 HTTP 409，错误码 `STUDENT_POSSIBLE_DUPLICATE`，附带候选摘要（id、姓名、学校、班级、状态），不返回联系方式。
2. 前端弹出确认框，明确“仍要创建”与“取消”。
3. 用户确认后带 `confirmPossibleDuplicate: true` 再次提交；服务端重新检查并在同一事务内插入，不静默跳过。
4. 同名但学校或班级不同不阻止创建；学校/班级为空时不作为精确重复条件，但仍可提示同名候选。

### 4.2 联系方式

不强制大陆手机号格式，以兼容座机、国际号码和临时联系方式。服务端进行字符集、长度和最少数字位数校验；前端仅提供即时提示。联系方式属于敏感字段，按 3.3 规则最小化展示。

### 4.3 入学日期

允许为空。非空时必须是合法公历日期，范围固定为 `1900-01-01 <= enrolled_at <= 服务端 Asia/Shanghai 当天`。不使用浏览器传入的当前日期作为权威值，不接受未来日期。

### 4.4 状态机

三个状态之间允许任意切换，同状态提交幂等：

```text
在读 ───────────────┐
  │                 │
  ├──> 待分配 <─────┤
  │                 │
  └──> 已结课 <─────┘
```

允许边集合为：在读↔待分配、在读↔已结课、待分配↔已结课。变更为已结课或从已结课恢复为在读前，前端二次确认；服务端只校验枚举和版本，不因关联数据自动阻止。状态变化：

- 不作废或修改合同，不改变合同有效性或到期日。
- 不删除、解绑或迁移学习记录和学习计划关系。
- 不取消、完成或重新派发任务。
- 首页只展示在读学生；学员管理默认可查看全部状态；详情对已结课学生仍可访问。

即使存在有效合同或待完成任务，服务端也不额外阻断结课或恢复在读。

### 4.5 无关联数据

新建学生默认为待分配且没有合同、记录、计划、任务分配。详情页基本信息正常显示；科目、到期时间、最近跟进、学习计划显示“—”；合同、学习记录和任务区域分别显示“暂无合同”“暂无学习记录”“暂无学习计划”“暂无任务分配”空状态。不创建占位行。

### 4.6 聚合职责边界

学生新增/编辑/状态 API 只写 `students`。科目、到期时间、最近跟进、计划、任务的来源、过滤和排序继续由 S2–S6 服务负责；档案保存成功后通过失效事件或重新查询刷新这些区域，不向 students 写冗余字段。

## 5. 页面与流程

### 5.1 学员管理页 `/students`

1. 顶部新增“新增学生”按钮，保持姓名搜索、年级/状态筛选、分页和表格布局。
2. 点击按钮打开新增侧栏；表单字段按 3.1 排列，不展示状态，负责人不出现；服务端固定以待分配创建。
3. 点击保存后按钮和关闭操作禁用，显示 loading；客户端先做体验校验，服务端再次校验。
4. 若返回可能重复 409，展示候选摘要和“仍要创建”；确认后按原草稿重试一次，不自动重试其他错误。
5. 创建成功后跳转 `/students/:id`，显示“学生已创建”；详情可返回列表。即使当前筛选不包含待分配，也不阻止跳转。
6. 创建失败保留草稿并显示字段/全局错误；列表不插入未确认的本地行。

列表不提供删除和状态批量操作；统一从详情维护档案，避免列表表格承载过多敏感字段。

### 5.2 学生详情页 `/students/:id`

1. 基本信息区保留紧凑左侧栏布局，增加“编辑档案”和“变更状态”入口。
2. 编辑档案打开侧栏，回填当前基础档案和 `version`；联系方式输入可编辑但视图仍脱敏。
3. 编辑只允许提交 3.1 中的基础字段，不含状态、负责人和聚合字段；成功留在详情页并刷新基本信息、学习记录、任务和聚合摘要。
4. 变更状态使用独立确认框，展示当前状态、目标状态和“不会删除关联数据”的说明；成功后刷新详情和相关列表/首页数据。
5. 路由切换、关闭侧栏或浏览器离开前，存在未保存修改必须确认；取消离开保留草稿。
6. 学生不存在继续展示 404 空状态；已结课学生保持详情可访问。

### 5.3 窄屏要求

- 侧栏在窄屏下使用全宽或接近全宽，表单主体独立滚动，底部保存/取消操作固定可见。
- 所有输入、选择器和日期控件宽度不超过视口；不因长姓名、学校或错误文案产生横向溢出。
- 状态确认框和可能重复候选列表可滚动，按钮顺序和键盘焦点可达。

## 6. API 契约

所有 API 遵守 `{status,msg,data}` envelope；成功 HTTP 200，创建 HTTP 201；错误使用 400/404/409/413/503，不返回 SQL、连接串、堆栈或联系方式候选。请求字段未知时 400，禁止静默忽略。

### 6.1 DTO

`StudentListItem` 保持现有字段：

```text
id, name, grade, className, school, status,
subjects: string[], expiryDate: string|null,
plans: { id: string, title: string }[], lastFollowUp: string|null
```

`StudentDetail` 在现有基础上增加：

```text
id, name, grade, className, school, gender, enrolledAt,
createdAt, guardianName, guardianPhoneMasked, note, status,
owner: { id: string, name: string } | null, version,
subjects, expiryDate, plans, lastFollowUp
```

编辑侧栏打开时调用独立的 `GET /api/students/edit` 获取 `StudentEditView`，不改变列表/详情的脱敏 DTO；明文仅限当前无登录的受控合成环境。

### 6.2 接口清单

| 方法与路由                   | 请求字段                                                                                                                  | 成功响应              | 调用页面         |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------- | --------------------- | ---------------- |
| `GET /api/students/list`     | `page、pageSize、keyword?、grade?、status?`                                                                               | `P<StudentListItem>`  | 学员管理         |
| `GET /api/students/detail`   | `id`                                                                                                                      | `StudentDetail`       | 学生详情         |
| `GET /api/students/options`  | `page、pageSize、keyword?`                                                                                                | `P<StudentOption>`    | 合同/任务选择器  |

| `PATCH /api/students/update` | `id、expectedVersion、name、grade、school?、className?、gender?、enrolledAt?、guardianName?、guardianPhone?、note?`       | `StudentDetail`       | 学生详情编辑     |

### 6.3 错误码

| HTTP | code                                            | 场景与前端行为                                                           |
| ---- | ----------------------------------------------- | ------------------------------------------------------------------------ |
| 400  | `VALIDATION_ERROR`                              | 字段缺失、超长、枚举、日期、联系方式、未知字段；按 fields 展示并保留草稿 |
| 404  | `NOT_FOUND`                                     | 学生不存在或已被其他环境移除；详情展示 404，列表刷新                     |

| 409  | `VERSION_CONFLICT`                              | 编辑/状态版本过期；保留草稿，提示重新加载                                |

| 503  | `DEV_ACTOR_UNAVAILABLE` / `STORAGE_UNAVAILABLE` | 开发操作人或数据库不可用；不显示为空，不自动重试                         |

## 7. 数据库、事务与并发

### 7.1 version 迁移（已确认）

为 `students` 增加 `version INT UNSIGNED NOT NULL DEFAULT 1` 和 `CHECK (version > 0)`，迁移文件为 `database/migrations/007_students_version.sql`。迁移策略：

1. 迁移前校验批准数据库、当前台账和 students 表结构；不读取或输出真实 `.env` 值。
2. 使用单一显式 DDL 增加列与约束；DDL 不假定可由普通事务回滚。
3. 迁移后检查所有学生 version 非空且为正整数，再记录版本、checksum、applied_at。
4. 先部署兼容读取，再在迁移确认后开放新增/编辑/状态写入口；旧应用不得在 version 缺失时写入。
5. 回滚优先回退应用并保留 version 列；删除列属于不可逆操作，须另行批准，不提供自动 down。

### 7.2 写事务

- 新增：在一个事务中校验数据库边界、字段和可能重复候选，插入 students，提交后按新 ID 查询详情及聚合结果；不写其他表。
- 编辑：事务内执行单行白名单 UPDATE，条件为 `id + expectedVersion`，同时更新 `updated_at` 和 `version=version+1`；影响行数为 0 时查询区分 404/409，失败回滚。
- 状态：与编辑相同的版本条件更新，仅修改 status、updated_at、version；同状态幂等不增加版本，不触碰任何关联表。
- 每次写操作使用连接池、参数化 SQL 和 finally 释放连接；提交前再次确认数据库边界；错误响应只返回安全错误码。
- 不做请求自动重试，不引入技术幂等回执。网络结果不明时由前端先刷新列表/详情核对，再由用户决定是否重试。

### 7.3 并发规则

`version` 同时保护档案字段和状态字段。两个窗口对同一学生进行编辑时，先成功者 version+1，后提交者收到 409；后者草稿不丢失，用户明确选择重载后才覆盖本地草稿。状态更新也必须带 expectedVersion，不能使用无条件 toggle。

| 同名合理 | 同名不同学校或班级                                       | 不阻止创建                                 |
| 并发     | 两窗口相同 version 编辑                                  | 一个成功，一个 409；失败草稿保留           |
| 并发状态 | 编辑与状态更新竞争                                       | 一个成功，一个 409；不出现半更新           |
| 关联保护 | 结课前后比较合同、记录、计划关系、任务分配               | 数据行和外键关系完全不变                   |
| 空关联   | 新学生详情和各区域                                       | 聚合为空、表格空状态，不创建占位行         |
| 跨页刷新 | 新增/编辑/状态后列表、详情、首页切换                     | 查询结果一致；首页只计在读                 |
| 异常     | 404、数据库503、操作人缺失、413                          | 安全错误反馈，绝不回退 mock 或显示成功     |
| 安全     | body 传 owner/actor/version/聚合字段、SQL 注入式输入     | 400 拒绝未知或禁止字段，数据不越权、不泄露 |
| 窄屏     | 320/375px 表单、错误、重复候选                           | 可滚动、按钮可见、无横向溢出               |

## 9. 可测试验收标准

1. 学员管理页有新增入口，成功创建后能进入新学生详情；失败不产生本地假数据。
2. 新增和编辑字段、默认值、必填、长度、枚举、联系方式和日期校验与本文一致。
3. 可能重复学生不会被静默创建；确认流程能创建新记录，同名不同学校/班级不被错误阻止。
4. 详情页有编辑档案和状态变更入口；负责人、合同、记录、计划、任务和派生字段不可由档案表单编辑。
5. 在读、待分配、已结课按状态机切换；已结课仍可访问详情，不触发删除、解绑、作废或任务迁移。
6. 首页只显示在读学生，学员管理状态筛选和详情状态标签一致。
7. 新学生无关联数据时，合同/记录/计划/任务区域展示正确空状态，刷新后仍一致。
8. 编辑与状态更新均携带 expectedVersion；冲突返回 409，草稿保留，用户确认重载后才覆盖。
9. 列表、详情、首页的科目、到期时间、最近跟进、计划和任务仍由对应聚合服务提供，档案写入不产生冗余字段。
10. 所有保存按钮在请求期间禁用；成功、400、404、409、413、503 有明确反馈，不自动重试写请求。
11. 联系方式在列表不返回、详情默认脱敏；错误响应不包含 SQL、配置、堆栈或其他学生隐私。
12. 窄屏表单、状态确认框和重复候选列表可操作、可滚动且无布局溢出。

## 10. 明确不做

- 不新增删除、软删除、删除后的恢复、批量操作或解除关系接口；“已结课→在读”使用状态更新接口。
- 不在学生写接口中创建/更新合同、学习记录、学习计划、任务定义、任务分配。
- 不在本模块实现负责人分配、登录、角色权限、审计、提醒、风险标记或家长端。
- 不为同名学生建立强制唯一约束，不以状态切换自动改变合同有效性或任务状态。
- 不在迁移阶段清库、覆盖合成数据、修改其他表结构或自动执行种子。
