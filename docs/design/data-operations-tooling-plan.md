## 实施顺序与契约

1. 修复学生脚本：稳定ID、显式版本，编辑回填只在内存中合并；省略保留，`--clear`明确清空可空字段，禁止状态/作者/聚合字段混入。
2. 复用公共本机HTTP、超时、禁止重定向、严格参数白名单和安全投影。明确、单义的用户指令即为本次写授权；学管助理在同一指令上使用内部 `--apply --confirm`，不要求重复询问。参数变化、目标不清或影响异常时才暂停。
3. 补齐学习记录list/get/create/update，任务定义list/get、分配list/get/assign/completion，以及合同/计划list/get（只读）。沿用已确认分类、日期、版本、1–100人整批规则，无任务定义维护扩展。
4. 无单条读取API的记录/分配，按学生及稳定ID在现有分页接口中有界定位，最多20页×100条；超过界限停止人工定位，不擅自新增接口或截断后宣称不存在。
5. 输出操作目标、脱敏变更预览、预计影响数量；确认写入后回读核实。写入结果不明只做一次有界只读核对，不重发；创建相似候选不能证明本请求已成功。错误/异常不能回显底层消息、完整电话、请求体。
6. 联系方式新增/变更只从本机stdin JSON输入，不接受命令行明文，避免shell历史；未变更电话从edit视图内存保留。自由文本输出额外去除控制字符并屏蔽疑似电话号码；仍禁止输入真实隐私。
7. 更新脚本使用文档、skill的开发/待验收边界和测试报告，完成格式、类型、Lint、单元、构建及本机只读/隔离HTTP验证。

## 本机操作人初始化（已确认的开发基础设施）

空 `users` 表时，`database/init-dev-actor.mjs` 是唯一允许建立开发操作人的入口。它使用保留合成名称、单一执行锁与事务：仅在人员总数为0时插入1行；已存在唯一同名合成人员时只复用；任何其他人员状态均停止。每个写入/提交前复核 `DATABASE() = 'tutor_workspace'`，不写 `.env`、学生或任何业务表；无自动删除/回退。用户在本机终端取得 ID 后私下填写 `DEV_ACTOR_ID` 并重启服务，学管助理不执行初始化。

真实业务写入仍要由学管助理取得明确、单义的用户指令，并由脚本完成稳定 ID、版本、日期和回读检查。无需单独产品或测试对话；缺失规则先由开发写最小设计，脚本缺口由学管助理交接给开发。
