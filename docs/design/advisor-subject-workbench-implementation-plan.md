## 目标与边界

让所有登录账号以自身负责学科作为首页默认视图；英语只是某个账号的配置值，不能硬编码。负责学科是视图偏好，不代替学生负责人权限，也不改写 `students`、合同、学习记录、任务、计划或既有审计语义。

本期包含关系表、当前用户读写契约、Header 个人设置入口和首页科目筛选；不包含科目主数据、批量分配负责学科、负责人改派规则、根据科目自动分配学生或修改任何真实业务合同。

## 交付切片

1. **数据与规则**：020 迁移、迁移白名单、Subject 规范化、`user_accounts.version` 乐观锁、审计和关系读写单测。
2. **当前用户契约**：扩展 `/api/auth/me`；增加本人负责学科读写接口，复用 Cookie、CSRF、401/409/503 envelope。
3. **个人设置**：在 Header 的个人设置中维护多选学科；远程科目选项复用合同已有选项，保存成功刷新 CurrentUser。
4. **首页**：`useHome` 初始为 `subjectMode=responsible`，增加多选科目与“恢复我的负责科目”操作；服务端按有效合同批量/参数化过滤，保留分页与现有年级、标签筛选。
5. **验证**：数据库约束、接口鉴权/冲突、首页组合筛选、无配置引导、桌面与 375px/320px 浏览器检查。

## 查询与性能

首页不得先把所有学生或所有合同读入前端筛选。主学生 COUNT 和分页 SELECT 以同一个 `EXISTS (SELECT 1 FROM contracts ...)` 过滤有效合同科目；合同状态表达式复用当前 `studentContractAggregates` 的 Asia/Shanghai 口径。随后仍只针对当前页学生批量查询科目、计划、标签、待办与动态，不能引入逐卡查询。

`subjectMode=responsible` 读取当前用户关系；`selected` 的科目由服务端重新校验，`all` 不读取关系。查询参数最多 10 个科目并有固定 pageSize 上限，任何未知参数或重复规范化值返回 400。

## 回退

应用回退可隐藏个人设置与首页筛选入口，但保留 020 结构、关系和审计数据；不得自动删表、清空负责学科或改写学生/合同数据。是否撤销结构须另行获得破坏性变更授权。

## 实现与验证记录

- 020 迁移已显式应用，复跑通过校验和与结构检查后安全跳过；未写入任何负责学科关系或业务数据。
- 当前用户 DTO、本人设置、乐观锁、替换关系与审计使用 `server/db/responsible-subjects.ts`，写 API 继续经过全局会话、同源 CSRF 和事务边界。
- 首页 COUNT 与分页 SELECT 共用有效合同科目 `EXISTS`；多个科目为 OR，与权限、在读、年级、标签为 AND；当页聚合流程保持不变。
