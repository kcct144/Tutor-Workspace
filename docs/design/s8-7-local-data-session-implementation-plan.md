# S8.7 本机日常数据操作会话实施计划

状态：已完成，等待受控本机手工复验（2026-09-07）

## 目标与边界

为 `scripts/` 中已验证的数据操作命令接入 S8.2 的本机回环登录 API。脚本只通过 HTTP API 工作，保留现有 `tutor_workspace` 只读预检；不直连业务 SQL、不伪造用户身份、不读取或修改 `.env`，不新增权限、迁移、账号或业务数据。

会话仅适用于当前 Windows 系统用户和回环 HTTP 服务。它不是远程访问、长期 Token 或无人值守凭据方案。

## 实施步骤与进度

1. **会话状态库（完成）**：新增 Node 原生模块，固定将会话状态保存在工作区外的当前用户本地应用数据目录；目录和文件以仅当前用户（及系统）可读写的 ACL 建立。状态只保存回环基地址、会话 Cookie 和 CSRF 值，不保存密码；原子写入、严格结构校验、可显式清除。
2. **交互式会话命令（完成）**：新增 `login`、`whoami`、`logout` 与 `clear` 命令。登录仅在 TTY 中读取隐藏的用户名/密码，向 `POST /api/auth/login` 发送同源请求，捕获 Cookie 后保存。用户名或密码不接受命令行、环境变量或文件输入。
3. **数据 API 客户端接入（完成）**：每次请求读取本机状态，绑定既有本机回环基地址；自动携带会话 Cookie，写请求加 `Origin` 与 CSRF 头。401 或 CSRF 403 清除本地状态并要求重新登录；网络异常和写入结果不明不重试、不擅自清除或重发。
4. **使用说明与 skill（完成）**：把 `actorReady` 改为仅数据库历史检查，不再作为写入资格；说明会话位置、有效期由服务端（空闲 8 小时、绝对 7 天）裁决、退出与手动清理、以及当前 OS 用户/恶意本地进程的威胁边界。
5. **隔离测试与交付（完成）**：以临时目录和回环 HTTP 夹具验证登录、失败、缺失/失效会话、CSRF 写请求、退出、无秘密输出与 API 边界；不创建账号或业务数据。完成后记录实测/跳过项。

## 失效与结果不明规则

- `401 UNAUTHENTICATED`、`403 CSRF_INVALID`、退出成功：删除本地状态，提示运行登录命令。
- 登录失败、会话缺失、会话文件异常：停止，不创建或猜测身份。
- 网络失败、超时或写入结果不明：不自动重试；保留会话并沿用现有回读核对流程。
- `logout` 无法确认服务端结果时保留本地状态并停止；`clear` 仅删除本地文件，明确服务端会话可能会存活到其失效。

## 验收判定

本切片只交付脚本会话桥接。真实管理员密码不由开发使用；真实登录成功与既有 API 的角色范围由用户在本机按文档手工复验。所有自动测试均为隔离夹具，不访问真实业务数据。
