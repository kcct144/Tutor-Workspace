# 学生详情与学生档案维护（S1–S6 查询 + S7 档案维护）

- 状态：已实现（详情查询、档案维护与详情布局优化）
- 负责人：产品经理兼数据库设计负责人
- 创建日期：2026-09-05
- 最后更新日期：2026-09-14
- 关联需求：S1 学生基础、S2 合同聚合、S3 学习记录、S4 学习计划、S6 任务分配、S7 学生档案维护、S9 成绩记录、学生标签、计划任务完成度

## 1. 页面结构与职责

详情页采用“左侧档案栏 + 右侧高频工作区”两栏结构：

1. **左侧档案栏**：桌面端窄栏吸顶，移动端恢复上下布局；展示学生基础档案、只读聚合信息和学生标签。
2. **右侧高频工作区**：使用页签在“学习记录”“成绩记录”“任务列表”之间切换；同一时间只展示一个表格，避免三个高频表格纵向堆叠。

本轮为基本信息区增加“编辑档案”和“变更状态”入口。编辑档案只改学生基础字段；合同、学习记录、学习计划、任务分配及负责人均不在本表单中维护。

## 2. 基本信息区

### 2.1 展示字段

姓名、年级、学校、班级、性别、入学日期、到期时间、建档时间、主要监护人、监护人联系方式、备注、当前学生状态、当前负责人、科目、进行中的学习计划、最近跟进。

其中：

- `科目`来自有效合同去重聚合；`到期时间`取有效时间合同最早结束日。
- `最近跟进`取所有学习记录 `MAX(occurred_on)`，不受记录列表当前筛选影响。
- `进行中的学习计划`来自真实多对多关系，只读展示 `{id,title}`，同名不同 ID 不合并。
- 任务数据来自真实任务分配，不写入 students 冗余字段。
- 空的基础字段统一显示“—”；负责人为空显示“未分配”；聚合列表为空显示“—”。详情只展示 `guardianPhoneMasked`，明文联系方式仅在编辑侧栏打开时单独请求。

### 2.2 编辑档案

- “编辑档案”打开侧栏表单，宽度约 480px，窄屏为全宽并保留固定底部操作栏。
- 可编辑：姓名、年级、学校、班级、性别、入学日期、监护人姓名、监护人联系方式、备注。
- 不可编辑：学生 ID、建档时间、负责人、当前状态、科目、到期时间、最近跟进、学习计划、任务列表。
- 点击保存后禁用表单与关闭操作，显示保存中；成功留在当前详情页，刷新基本信息和三个区域的查询结果。
- 失败保留草稿。400 显示字段错误，404 提示学生不存在，409 提示“档案已被其他窗口更新，请重新加载”，503 提示服务暂不可用；不自动重试。
- 若编辑中关闭侧栏、切换学生或离开页面，存在未保存修改时必须确认放弃；取消离开则保留草稿。

### 2.3 状态变更

- 当前状态旁提供“变更状态”入口，使用独立确认框，不混入基础档案保存。
- 目标状态仅允许在读、待分配、已结课；同状态提交为幂等。
- 已结课表示业务服务结束，不是删除；允许在确认后重新变更为在读。
- 确认文案明确：状态变化不会删除、解除或迁移合同、学习记录、学习计划和任务分配。
- 成功后刷新基本信息、学习记录、任务列表以及首页/列表相关查询；失败保持页面原状态。

### 2.4 学生标签

- 标签属于学生档案辅助信息，放在左侧档案栏的“进行中的学习计划”之后，不再占用右侧高频工作区。
- 保留独立 `StudentTagsPanel` 的查询、编辑、版本冲突、草稿保护和保存行为；布局上通过档案栏插槽或等价组合嵌入，不将标签读写逻辑复制进基础信息组件。
- 桌面端标签区与基本信息共用同一个左侧卡片，使用分隔线区分，避免出现嵌套卡片和重复留白；窄屏时随基础信息出现在页签之前。
- 标签编辑中切换右侧页签不得丢失草稿；学生路由切换时才按现有规则销毁旧学生的标签状态并加载新学生数据。

## 3. 高频工作区页签

- 页签固定为“学习记录”“成绩记录”“任务列表”，默认激活“学习记录”。页签标签不重复展示数量；各区自身标题继续显示各自总数。
- 首次进入详情页只加载默认学习记录。用户首次点击其他页签时再加载对应数据；已经访问过的页签保持挂载，切回时保留筛选条件、页码、已加载结果和未完成的表单草稿，不重复请求。
- 保存中禁止重复提交；页签切换不得中断保存。打开的模态框或侧栏继续由原组件控制，不能因页签切换被销毁。
- 每个页签的 loading、empty、error、重试和分页保持独立。未访问页签不能显示“暂无数据”；一个页签失败不得影响另两个页签或基础信息。
- 学生 ID 路由变化后，激活页签重置为“学习记录”，所有已访问页签按新学生重新初始化，旧响应不得覆盖新学生。

### 3.1 学习记录

- 学习记录分类仅缺/补/强；科目复用合同/任务统一的非空、trim 后最多 64 个 Unicode 字符规则，但允许为 `null`，表示“综合/通用跟进”。记录不关联或校验某一份合同，也不会修改合同、任务或学习计划。
- 学习记录支持按分类、科目、发生日期范围、内容关键词组合筛选，默认每页 5 条；列表无科目时显示“综合/通用”。
- 学习记录新增/编辑沿用既有 `POST/PATCH /api/learning-records/*` 契约；请求可带 `subject: string | null`，编辑需版本，不能修改学生归属和作者，不提供删除。

### 3.2 成绩记录

- 成绩记录复用 S9 真实区域和既有新增、编辑、筛选、分页、冲突处理规则；详情页新增时固定关联当前学生。
- 成绩记录与学习记录是两份独立数据，切换页签不会相互转换、复制或联动。

### 3.3 任务列表

- 任务列表按当前 `studentId` 查询真实任务分配，支持状态和标题关键词筛选，默认每页 5 条；完成切换使用任务分配 API，状态仅待完成/已完成。
- 三张表的分页、loading、empty、error 独立；任一区域失败不伪装成空列表，也不回退 mock。
- 正在编辑学习记录或成绩记录时刷新基本信息不能销毁草稿。

## 4. 业务边界

- 学生档案保存只写 `students`；不在同一请求创建合同、记录、计划关系或任务分配。
- 科目、到期时间、最近跟进、计划、任务是只读派生字段，不在新增/编辑档案表单中出现，也不接受写接口传入。
- 学生状态切换不改变合同有效性，不清空学习记录，不解除计划关系，不取消或完成任务。
- 新建学生无任何关联数据时，详情正常显示基础档案；科目、到期时间、最近跟进、计划显示“—”，学习记录和任务表展示各自空状态。
- 无效学生 ID 继续显示 404 空状态；已结课学生仍可进入详情并查看历史关联数据。
- 联系方式数据库保存原值，详情只展示 `guardianPhoneMasked`；编辑侧栏打开时请求 `GET /api/students/edit?id=<id>` 获取明文 `guardianPhone`，仅限当前无登录的受控合成环境。真实试用前必须由鉴权方案替换该边界。

## 5. 接口与数据契约

现有详情查询继续使用 `GET /api/students/detail?id=<id>`，响应增加 `version`、`guardianPhoneMasked`，并返回 `owner:{id,name}|null`；不返回明文联系方式。新增：

- `GET /api/students/edit?id=<id>`：仅在打开编辑侧栏时请求 `StudentEditView`，包含编辑所需的明文 `guardianPhone`，仅限当前无登录的受控合成环境。
- `PATCH /api/students/update`：`{id,expectedVersion,name,grade,school?,className?,gender?,enrolledAt?,guardianName?,guardianPhone?,note?}`；拒绝 status、owner 和聚合字段。
- `PATCH /api/students/status`：`{id,expectedVersion,status}`；仅更新状态和版本，不触碰关联表。

统一响应为 `{status,msg,data}`。写操作人不由浏览器传入，服务端从当前网页登录会话取得。

## 6. 可测试验收标准

- 详情基本信息区显示档案字段、负责人和聚合字段，并对空值使用统一空状态。
- 点击“编辑档案”可打开表单；必填、长度、枚举、日期和联系方式校验正确，保存中不可重复提交。
- 编辑成功后留在当前详情页，档案内容刷新；合同、记录、计划、任务数据保持原关联。
- 点击“变更状态”可在读/待分配/已结课之间切换；已结课不会导致任何关联数据删除或解除。
- 乐观锁版本冲突返回 409，编辑草稿不丢失；用户重新加载后可继续编辑。
- 新建学生从列表进入详情后，基本信息可见，合同/记录/计划/任务均展示空状态。
- 已结课学生在详情仍可查询历史记录和任务；首页不再统计该学生，列表可通过状态筛选找到。
- 标签显示与编辑位于左侧档案栏；桌面端不在右侧产生独立标签卡片，窄屏时位于页签之前。标签草稿不因页签切换丢失。
- 默认打开学习记录；首次切换成绩记录或任务列表才开始其查询，切回后保留各自筛选、页码和草稿。三页签的既有筛选、分页、错误反馈不回退或相互影响。
- 学生详情不展示“学习计划任务完成度”、计划进度卡片或该区 loading/error/empty 状态；左栏中的进行中学习计划标签仍保留。
- 窄屏下侧栏/表单可滚动，操作栏可见且无横向溢出。
- 新增、编辑记录可从既有合同科目选项选择科目；不选择会以 `null` 保存为综合/通用跟进。非法空白或超过 64 字符的非空科目被服务端拒绝，历史记录不会被回填。

## 2026-09-14：详情布局裁决（已实现）

- 从 `/students/:id` 移除“学习计划任务完成度”展示及其前端读取，不再渲染 `PlanProgressSection`，也不在进入学生详情时调用 `GET /api/students/plan-progress`。
- 这只是学生详情的信息架构调整：任务定义关联计划、任务分配快照、`/plans` 中的关联任务和学生完成度，以及既有迁移、API 和数据均保留，不做删除、回滚或数据迁移。
- 左栏继续以计划标签表达学生当前关联的学习计划；用户需要查看计划维度完成度时，进入对应学习计划页面。

实现对应：`BasicInfoPanel.vue` 的 `footer` 插槽组合原 `StudentTagsPanel`，标签仍由自己的 composable/service 读写；`students/[id].vue` 使用 Ant Design Vue Tabs 和 `useStudentDetailWorkspace` 管理“学习记录 / 成绩记录 / 任务列表”的首次挂载与访问状态。默认只创建学习记录组件，成绩与任务首次访问后保留挂载；路由学生 ID 改变时重置为学习记录并以新 ID 的 key 创建三个工作区组件。

页面已移除 `PlanProgressSection`，不再由学生详情触发学生计划进度请求；组件、service、API、018 迁移及 `/plans` 计划完成度均保留。桌面左栏吸顶，窄屏恢复普通文档流，学生标签位于页签前。实现验证见 `docs/test/task-plan-progress-acceptance.md` 的“学生详情布局优化验证”。

## 已确认基线与上线前置条件

- 新增成功后跳转 `/students/:id`；服务端固定以“待分配”创建，客户端不传 `status`。
- 结课与恢复在读均允许，无论是否存在有效合同或待完成任务；前端二次确认并说明关联数据不受影响，服务端不额外阻断。
- 当前负责人继续只读；本轮不引入操作人字段、审计历史或负责人分配。
- 不提供删除、软删除、删除后的恢复或任何关联解绑能力；“已结课→在读”仅作为状态变更保留。
- 真实用户试用前必须补齐登录鉴权、权限隔离和操作审计，并替换 `StudentEditView` 的受控无登录明文回填边界。
