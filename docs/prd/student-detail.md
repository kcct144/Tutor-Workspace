## 1. 页面结构与职责

详情页保持三个区域：

1. **基本信息区**：桌面端左侧窄栏吸顶，移动端恢复上下布局；展示学生基础档案和只读聚合信息。
2. **学习记录区**：展示缺/补/强记录，支持日期、分类、关键词筛选、分页、新增和编辑。
3. **任务列表区**：展示当前学生任务分配，支持关键词、状态筛选和分页；完成状态按任务分配模块规则维护。

本轮为基本信息区增加“编辑档案”和“变更状态”入口。编辑档案只改学生基础字段；合同、学习记录、学习计划、任务分配及负责人均不在本表单中维护。

## 2. 基本信息区

### 2.1 展示字段

姓名、年级、学校、班级、性别、入学日期、到期时间、建档时间、主要监护人、监护人联系方式、备注、当前学生状态、当前负责人、科目、进行中的学习计划、最近跟进。

其中：

- `科目`来自有效合同去重聚合；`到期时间`取有效时间合同最早结束日。
- `最近跟进`取所有学习记录 `MAX(occurred_on)`，不受记录列表当前筛选影响。
- `进行中的学习计划`来自真实多对多关系，只读展示 `{id,title}`，同名不同 ID 不合并。
- 任务数据来自真实任务分配，不写入 students 冗余字段。
- 空的基础字段统一显示“—”；负责人为空显示“未分配”；聚合列表为空显示“—”。详情只展示 `guardianPhoneMasked`，明文联系方式仅在编辑侧栏打开时单独请求。

### 2.2 编辑档案

- “编辑档案”打开侧栏表单，宽度约 480px，窄屏为全宽并保留固定底部操作栏。
- 可编辑：姓名、年级、学校、班级、性别、入学日期、监护人姓名、监护人联系方式、备注。
- 不可编辑：学生 ID、建档时间、负责人、当前状态、科目、到期时间、最近跟进、学习计划、任务列表。
- 点击保存后禁用表单与关闭操作，显示保存中；成功留在当前详情页，刷新基本信息和三个区域的查询结果。
- 失败保留草稿。400 显示字段错误，404 提示学生不存在，409 提示“档案已被其他窗口更新，请重新加载”，503 提示服务暂不可用；不自动重试。
- 若编辑中关闭侧栏、切换学生或离开页面，存在未保存修改时必须确认放弃；取消离开则保留草稿。

### 2.3 状态变更

- 当前状态旁提供“变更状态”入口，使用独立确认框，不混入基础档案保存。
- 目标状态仅允许在读、待分配、已结课；同状态提交为幂等。
- 已结课表示业务服务结束，不是删除；允许在确认后重新变更为在读。
- 确认文案明确：状态变化不会删除、解除或迁移合同、学习记录、学习计划和任务分配。
- 成功后刷新基本信息、学习记录、任务列表以及首页/列表相关查询；失败保持页面原状态。

## 3. 学习记录与任务区域（保持既有职责）

- 学习记录分类仅缺/补/强；支持按分类、发生日期范围、内容关键词组合筛选，默认每页 5 条。
- 学习记录新增/编辑沿用既有 `POST/PATCH /api/learning-records/*` 契约；编辑需版本，不能修改学生归属和作者，不提供删除。
- 任务列表按当前 `studentId` 查询真实任务分配，支持状态和标题关键词筛选，默认每页 5 条；完成切换使用任务分配 API，状态仅待完成/已完成。
- 两张表分页、loading、empty、error 独立；任一区域失败不伪装成空列表，也不回退 mock。
- 学生 ID 路由变化时取消或忽略旧请求，不能让旧学生响应覆盖当前页面；正在编辑学习记录时刷新基本信息不能销毁草稿。

## 4. 业务边界

- 学生档案保存只写 `students`；不在同一请求创建合同、记录、计划关系或任务分配。
- 科目、到期时间、最近跟进、计划、任务是只读派生字段，不在新增/编辑档案表单中出现，也不接受写接口传入。
- 学生状态切换不改变合同有效性，不清空学习记录，不解除计划关系，不取消或完成任务。
- 新建学生无任何关联数据时，详情正常显示基础档案；科目、到期时间、最近跟进、计划显示“—”，学习记录和任务表展示各自空状态。
- 无效学生 ID 继续显示 404 空状态；已结课学生仍可进入详情并查看历史关联数据。
- 联系方式数据库保存原值，详情只展示 `guardianPhoneMasked`；编辑侧栏打开时请求 `GET /api/students/edit?id=<id>` 获取明文 `guardianPhone`，仅限当前无登录的受控合成环境。真实试用前必须由鉴权方案替换该边界。

## 5. 接口与数据契约

现有详情查询继续使用 `GET /api/students/detail?id=<id>`，响应增加 `version`、`guardianPhoneMasked`，并返回 `owner:{id,name}|null`；不返回明文联系方式。新增：

- `GET /api/students/edit?id=<id>`：仅在打开编辑侧栏时请求 `StudentEditView`，包含编辑所需的明文 `guardianPhone`，仅限当前无登录的受控合成环境。
- `PATCH /api/students/update`：`{id,expectedVersion,name,grade,school?,className?,gender?,enrolledAt?,guardianName?,guardianPhone?,note?}`；拒绝 status、owner 和聚合字段。
- `PATCH /api/students/status`：`{id,expectedVersion,status}`；仅更新状态和版本，不触碰关联表。

统一响应为 `{status,msg,data}`。写操作人不由浏览器传入，服务端从当前网页登录会话取得。

## 6. 可测试验收标准

- 详情基本信息区显示档案字段、负责人和聚合字段，并对空值使用统一空状态。
- 点击“编辑档案”可打开表单；必填、长度、枚举、日期和联系方式校验正确，保存中不可重复提交。
- 编辑成功后留在当前详情页，档案内容刷新；合同、记录、计划、任务数据保持原关联。
- 点击“变更状态”可在读/待分配/已结课之间切换；已结课不会导致任何关联数据删除或解除。
- 乐观锁版本冲突返回 409，编辑草稿不丢失；用户重新加载后可继续编辑。
- 新建学生从列表进入详情后，基本信息可见，合同/记录/计划/任务均展示空状态。
- 已结课学生在详情仍可查询历史记录和任务；首页不再统计该学生，列表可通过状态筛选找到。
- 学习记录和任务表的现有筛选、分页、错误反馈不因档案维护改动而回退或相互影响。
- 窄屏下侧栏/表单可滚动，操作栏可见且无横向溢出。

## 已确认基线与上线前置条件

- 新增成功后跳转 `/students/:id`；服务端固定以“待分配”创建，客户端不传 `status`。
- 结课与恢复在读均允许，无论是否存在有效合同或待完成任务；前端二次确认并说明关联数据不受影响，服务端不额外阻断。
- 当前负责人继续只读；本轮不引入操作人字段、审计历史或负责人分配。
- 不提供删除、软删除、删除后的恢复或任何关联解绑能力；“已结课→在读”仅作为状态变更保留。
- 真实用户试用前必须补齐登录鉴权、权限隔离和操作审计，并替换 `StudentEditView` 的受控无登录明文回填边界。
