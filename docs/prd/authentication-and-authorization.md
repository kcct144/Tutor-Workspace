# 登录验证与权限管理（S8 MVP）

- 状态：已确认
- 负责人：产品经理兼技术设计负责人
- 创建日期：2026-09-07
- 最后更新日期：2026-09-07
- 关联需求：登录验证、账号管理、学生数据权限隔离、操作审计、现有业务 API 鉴权

## 1. 目标与范围

本模块为内部“学管师工作台”增加最小可用的真实身份边界：管理员创建账号，用户以账号密码登录，服务端通过会话识别当前用户，并按角色与学生负责人关系限制数据访问。所有关键业务写入记录真实操作人和审计事件。

本模块完成后，`DEV_ACTOR_ID` 不再是浏览器或数据工具访问业务 API 的身份来源，也不存在“未登录但可以访问业务接口”的兼容分支。

MVP 包含：

1. 账号密码登录、退出、当前用户查询和修改本人密码。
2. 管理员创建、启用、停用账号，以及重置临时密码。
3. 固定的“管理员 / 学管师”两角色权限模型。
4. 基于 `students.owner_user_id` 的学生及关联业务数据隔离。
5. 未分配学生池、学管师认领、管理员分配或改派负责人。
6. 学生、合同、学习记录、任务定义、任务分配等现有 API 的服务端鉴权。
7. 学生、合同、学习记录和任务分配关键写操作的追加式审计；同时覆盖账号、负责人和任务定义变更。

明确不包含：

- 公开注册、短信验证码、邮箱验证、找回密码邮件、第三方登录、单点登录或多因素认证。
- 多租户、部门、校区、复杂组织树、动态角色、权限点配置或字段级自定义权限。
- Redis 会话集群、JWT 刷新令牌、跨域前后端或移动端 Token。
- 账号物理删除、审计日志删除、用户冒充、批量改派或公开部署。
- 以登录模块为由新增学生、合同、记录、计划或任务的业务功能。

登录上线不改变当前“仅回环地址、本机使用”的部署边界；对外或多人远程部署必须另行完成 HTTPS、网络边界和安全评审。

## 2. 目标用户与角色

### 2.1 管理员

管理员负责初始化和维护账号、查看全量数据、分配学生负责人以及查看审计记录。管理员不是数据库管理员，不能通过页面执行迁移、SQL、清库或物理删除。

### 2.2 学管师

学管师负责自己名下学生的档案、合同、学习记录和任务日常工作；可新增学生，新增后由服务端归属给当前学管师。除未分配学生池的最小摘要外，学管师不能看到其他学管师负责的学生及其关联数据。

## 3. 推荐的 MVP 权限模型

权限由服务端固定策略实现，不新增“角色—权限点”配置表。页面隐藏只是体验优化，不能代替 API 鉴权。

| 业务范围          | 管理员                                 | 学管师                                                                                               |
| ----------------- | -------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| 首页              | 查看全部在读学生及全局数量             | 只查看本人负责的在读学生，数量也按本人范围计算                                                       |
| 学生列表/详情     | 查看全部学生，包括未分配和已结课       | 查看本人负责的学生；另可查看未分配池最小摘要                                                         |
| 新增学生          | 允许；沿用 S7 默认业务状态，负责人为空 | 允许；服务端将负责人固定为当前学管师，不能指定其他负责人                                             |
| 编辑学生档案/状态 | 允许操作全部学生                       | 仅允许操作本人负责的学生                                                                             |
| 学生负责人        | 分配、改派、取消分配                   | 只能从未分配池认领给自己，不能改派或取消分配                                                         |
| 监护人联系方式    | 可按现有编辑回填契约访问全量学生       | 仅可访问本人负责学生；未分配池不返回联系方式                                                         |
| 合同              | 查看、新增、编辑全部合同               | 仅限本人负责学生的合同                                                                               |
| 学习记录          | 查看、新增、编辑全部学生记录           | 仅限本人负责学生；可编辑该学生既有记录，原作者不改变                                                 |
| 学习计划          | 查看、编辑全部文档                     | 查看本人负责的文档，以及关联到本人学生的文档；仅编辑本人负责的计划文档                               |
| 任务定义          | 查看、创建、编辑、启停全部定义         | 查看全部启用定义和本人负责的停用定义；创建、编辑、启停本人负责的定义；可用任意启用定义向本人学生派发 |
| 任务分配          | 查看、创建、完成/恢复全部分配          | 仅限本人负责的学生；批量中任一学生越权则整批失败                                                     |
| 账号与角色        | 创建、启停、改角色、重置密码           | 仅查看本人信息和修改本人密码                                                                         |
| 审计日志          | 只读查看全部审计                       | 不可访问                                                                                             |

任务定义的 `owner_user_id` 在本模块启用后解释为稳定的负责用户：创建时写入当前用户，普通编辑不再改写；管理员可管理全部定义。所有启用任务定义对已登录用户可见，学管师可用其他负责人创建的启用定义向本人学生派发，但不能维护该定义。任务分配不保存任务标题、科目或说明快照，历史展示始终 JOIN 最新任务定义；任务定义编辑不会改写分配记录本身。学习计划沿用同样的负责人边界，已有负责人数据不追溯改写。

## 4. 学生归属、未分配与认领

### 4.1 权限关系

- 管理员对所有学生及关联业务数据有访问权。
- 学管师的普通查询必须满足 `students.owner_user_id = 当前用户 ID`。
- 学管师新增学生时，服务端在同一创建事务中将 `owner_user_id` 固定写为当前会话用户；请求体不得提供负责人、操作人、状态或版本。学生负责人归属不等于学生业务状态，默认状态继续沿用既有 S7 规则。
- 学生直接 ID 越权时统一返回 404 `NOT_FOUND`，避免泄露其他用户的数据是否存在。
- 列表总数、筛选项、任务数量、合同科目和首页统计都必须在权限过滤后计算，不能先查询全量再由前端过滤。

### 4.2 未分配学生池

未分配池只包含 `owner_user_id IS NULL` 且状态为“待分配”的学生，向学管师返回：`id、name、grade、school、className、status、version`。不返回监护人、联系方式、备注、合同、记录、计划或任务信息。

学管师可点击“认领”：

1. 前端二次确认认领对象。
2. 服务端在单事务中检查账号启用、学生仍未分配及版本一致。
3. 只把 `owner_user_id` 设置为当前用户并递增 `students.version`；学生状态保持“待分配”，由学管师按现有状态流程另行改为“在读”。
4. 两人同时认领时只允许一人成功，另一人收到 409 `OWNERSHIP_CONFLICT`。

管理员可把学生分配给任一启用账号、改派或取消分配；负责人变化不自动更改学生状态、合同、记录、计划或任务。所有负责人变更都必须写审计。

## 5. 登录、账号与密码流程

### 5.1 登录方式

- 登录页使用“账号 + 密码”，不支持公开注册。
- 账号由管理员创建；用户名由服务端转为小写，长度 3–64，只允许 ASCII 字母、数字、点、下划线和连字符，且全局唯一。
- 登录失败统一提示“账号或密码错误”，账号不存在、密码错误、账号停用或临时锁定不得使用不同文案或响应时间显著区分。
- 连续失败采用数据库计数：15 分钟窗口内达到 5 次后锁定 15 分钟；不引入 Redis。成功登录清零失败计数。

### 5.2 初始管理员

初始管理员不写入迁移、种子或 `.env`，由仅可在本机终端运行的一次性引导命令建立：

1. 先确认当前数据库为 `tutor_workspace`，并确认不存在已启用管理员账号。
2. 当前环境优先显式选择一个既有 `users.id` 绑定账号，以保留现有人员及历史外键；全新空库可在同一事务创建 `users` 人员行和管理员账号。
3. 用户名由操作者输入；密码使用隐藏输入并输入两次，不允许出现在命令参数、日志或 shell 历史中。
4. 创建成功后立即成为唯一初始管理员；再次执行时若已有启用管理员必须拒绝。

该流程不会自动读取或信任 `DEV_ACTOR_ID`，也不会修改 `.env`。

### 5.3 账号状态

- 账号只有“启用 / 停用”。停用后不能登录，现有会话立即失效。
- 账号不提供删除；停用不会改变其历史外键、学生归属或审计记录。
- 系统必须保证至少一个启用管理员：禁止停用最后一个启用管理员，也禁止把最后一个启用管理员改为学管师。

### 5.4 密码规则

- 密码长度 15–128 个 Unicode 字符，同时限制 UTF-8 输入最多 512 字节；不自动 trim、不静默截断。
- 允许空格和常见 Unicode 字符，不强制大小写、数字或特殊符号组合。
- 密码不得与规范化用户名完全相同；服务端拒绝内置高频弱密码表中的值。
- 密码使用带独立随机盐的 Argon2id 单向哈希存储，数据库和日志永不保存明文。
- 不要求定期修改密码；首次临时密码、管理员重置或安全事件后要求修改。

### 5.5 修改与重置

- 用户修改本人密码必须已有有效会话、输入当前密码和新密码；成功后撤销其他会话并轮换当前会话。
- 管理员不能查看任何密码。重置时系统生成 20 字符一次性临时密码，只在成功结果中显示一次，不写日志；账号标记为“下次登录必须修改”，原会话全部撤销。
- MVP 不提供“忘记密码”自助流程；无法登录时由管理员重置。初始管理员本人遗忘且没有第二管理员时，只能走本机受控恢复流程，该流程必须另行实现并记录审计，不能通过数据库手工改明文。

## 6. 登录会话与退出

推荐使用服务端不透明会话，而不是 JWT：浏览器只持有随机会话 ID，角色、账号状态和过期信息由 MySQL 会话表管理，便于停用账号、改角色、修改密码后立即撤销。

- 会话 ID 使用 32 字节密码学安全随机数；数据库只保存其 SHA-256 摘要。
- Cookie 为 `HttpOnly、SameSite=Strict、Path=/、无 Domain`。HTTPS 环境必须使用 `Secure` 和 `__Host-` 前缀；当前 HTTP 本机开发仅允许在严格回环地址模式关闭 `Secure`。
- 空闲有效期 8 小时，绝对有效期 7 天；没有“记住我”。服务端时间为权威。
- 每个 API 请求都在服务端验证会话、账号状态和角色；不能只依赖前端路由守卫。
- 退出登录撤销当前会话并清除 Cookie；退出后浏览器后退也不能重新读取受保护数据。
- Cookie 会话的写请求使用同源校验和与会话绑定的 CSRF Token；Token 不存入 localStorage/sessionStorage。
- Redis 不参与会话；过期会话由登录时或受控维护任务分批清理，Redis 不可用不影响登录。

## 7. 页面与交互

### 7.1 登录页 `/login`

- 字段：账号、密码；支持密码管理器和粘贴。
- 提交期间禁用按钮；成功跳转到已校验的站内原目标，默认首页。
- 错误密码、停用、锁定、账号不存在使用同一提示；网络或存储故障单独提示“登录服务暂不可用”。
- 已登录用户访问登录页自动进入首页；必须修改临时密码的用户跳转 `/account/password`。

### 7.2 全局 Header

展示当前用户姓名和角色，提供“修改密码”和“退出登录”。不展示内部用户 ID、会话 ID 或权限调试信息。

### 7.3 账号管理 `/settings/users`

仅管理员可见。支持分页、按姓名/用户名搜索、角色和状态筛选，以及创建账号、启停、改角色、重置密码。所有提交有 loading、成功、失败和 409 版本冲突反馈；不提供删除。

### 7.4 审计日志 `/settings/audit`

仅管理员只读。支持时间范围、操作人、动作类型、学生 ID/姓名筛选和分页。详情展示脱敏后的变更摘要，不展示密码、会话、CSRF、监护人明文联系方式或学习记录全文。

### 7.5 无权限与会话失效

- 未登录访问受保护页面，跳转 `/login?redirect=<站内路径>`。
- 已登录但角色无权访问页面，展示 403 页面并提供返回首页。
- 会话过期或被撤销时清空前端用户状态并跳转登录；写操作草稿尽量保留在页面内存，重新登录后由用户决定是否重提。
- 窄屏下登录表单、账号侧栏、临时密码结果和审计详情均不得横向溢出，关键操作保持可见。

## 8. API 鉴权与错误契约

公开白名单仅包含：

- `POST /api/auth/login`
- `GET /api/health`（只返回服务可用性，不返回数据库、账号或配置细节）

`GET /api/auth/me`、退出和其余全部 `/api/**` 都要求有效会话。所有响应继续使用 `{status,msg,data}`。

| HTTP | code                       | 含义                                             |
| ---- | -------------------------- | ------------------------------------------------ |
| 401  | `INVALID_CREDENTIALS`      | 登录失败统一响应，不说明账号是否存在、停用或锁定 |
| 401  | `UNAUTHENTICATED`          | 缺少、无效、过期或已撤销会话；服务端清除 Cookie  |
| 403  | `FORBIDDEN`                | 已登录但角色不允许执行该页面或动作               |
| 403  | `PASSWORD_CHANGE_REQUIRED` | 临时密码尚未修改，只允许当前用户、改密和退出接口 |
| 403  | `CSRF_INVALID`             | 写请求同源或 CSRF 校验失败                       |
| 404  | `NOT_FOUND`                | 资源不存在，或资源存在但不属于当前学管师         |
| 409  | `VERSION_CONFLICT`         | 账号、学生或业务记录版本过期                     |
| 409  | `OWNERSHIP_CONFLICT`       | 学生已被他人认领或负责人已变化                   |
| 413  | `PAYLOAD_TOO_LARGE`        | 请求体超限                                       |
| 503  | `STORAGE_UNAVAILABLE`      | 数据库不可用；不回退为未鉴权或 mock 数据         |

浏览器不得提交 `actorId、ownerUserId、assignedBy、authorUserId、createdBy、updatedBy、role` 等服务端身份字段；允许管理员负责人管理接口提交目标负责人 ID，但操作人仍只能来自会话。

## 9. 最小审计范围

以下成功写操作必须记录“谁、何时、对什么对象、执行什么动作、哪些非敏感字段发生变化”：

- 学生：新增、基础档案修改、状态变更、负责人分配/改派/取消、认领。
- 合同：新增、修改。
- 学习记录：新增、修改；只记分类、发生日期和“正文已变化”，不保存正文副本。
- 任务分配：批量创建时每条分配均可追溯同一请求；完成、恢复待完成。
- 账号：创建、启停、角色变更、密码重置；不记录密码值或密码哈希。
- 任务定义：新增、修改、启停。

审计与业务写入必须在同一数据库事务内完成；审计失败则业务写入回滚。失败的业务请求不伪造“成功审计”，登录失败只进入安全日志和失败计数，不写入包含明文账号/密码的业务审计。

## 10. 数据工具与 `DEV_ACTOR_ID` 迁移

- `users` 继续作为人员身份主表，现有所有外键保持有效；账号凭据放在一对一账号表，不把密码加入业务 DTO。
- 当前 `DEV_ACTOR_ID` 对应的人员可由初始管理员引导显式绑定账号，但不会被自动信任或自动升级。
- 鉴权切换后，HTTP API 不再读取 `event.context.devActorId`，各写操作从服务端会话取得当前 `userId`。
- 合同 `created_by/updated_by`、记录 `author_user_id`、任务分配 `assigned_by` 和各 owner 字段继续引用 `users.id`，无需重写历史数据。
- 现有数据操作脚本不能使用本机地址或 `DEV_ACTOR_ID` 绕过鉴权。首次由受控本机交互式登录建立短期会话；会话 Cookie 与 CSRF 信息仅保存到 Git 忽略、工作区外且仅当前系统用户可访问的本地安全目录，后续命令复用该会话，不要求每条命令重复输入密码。
- 退出、会话过期、改密、账号停用或角色变更后，脚本必须清除本地会话状态并要求重新登录。不得新增长期 API Token、无头凭据或远程访问能力；密码、Cookie、CSRF 信息不得出现在聊天、命令参数、日志、Git 或 `.env`。
- 不为历史操作伪造审计记录；审计只从鉴权模块启用时开始。

S8 经确认后，将覆盖 S7“当前负责人只读”的阶段性限制，但只新增独立的认领和管理员负责人接口；学生基础档案表单仍不能直接写 `ownerUserId`。

## 11. 可测试验收标准

1. 初始管理员只能通过本机受控引导建立，迁移、种子、代码和日志中不存在固定密码。
2. 启用账号可正常登录；错误密码、未知账号、停用和锁定使用统一失败反馈。
3. 会话 Cookie 不可被前端脚本读取；退出、停用账号、重置密码后原会话不能继续访问 API。
4. 管理员可查看全部学生，学管师的列表、总数、详情、首页和关联业务只包含本人负责学生。
5. 学管师直接访问他人学生或其合同、记录、分配时返回 404，管理员专属账号/审计接口返回 403。
6. 未分配池不泄露联系方式或关联数据；并发认领只有一人成功。
7. 学管师批量派发任务时若混入一个越权学生，整批不创建。
8. 账号停用、角色变更和学生改派在下一次请求立即生效，不依赖 Redis 或前端刷新权限缓存。
