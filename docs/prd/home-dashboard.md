## 本轮确定的需求

以下旧版描述及 S6 章节保留作历史说明；当前卡片展示、DTO 与刷新以本文 S12 章节为准。

首页以学生卡片为主要信息区，取消独立数据区与问候语。页面顶部保留工作台标题、在读学生数量、添加学生/新建任务快捷操作和年级筛选。卡片固定高度，响应式网格自动适配屏幕宽度；每张卡片展示学生姓名、年级与合同科目（普通文字同一行）、学习计划标签、右下角详情入口，不展示班级。学习计划直接展示标签，不增加“学习计划”字段标题。学生在 7 天内到期时，在姓名旁展示“n 天后到期”状态标签。任务区拆分为“未完成”和“已完成”两组，各最多显示 3 条；超过 3 条时显示剩余数量提示。任务通过复选框调用真实API切换并持久化完成状态，已完成任务显示删除线。

应用 header 仅保留图形 logo，不显示“学管师工作台”文字，以减少横向占用；logo 链接仍保留无障碍名称。

## 已确认范围

1. 保留快捷操作轻量提示，不新增学生写能力。
2. 真实多对多计划标签，按计划ID区分。
3. 允许首页复选框切换完成状态，与分配页及学生详情同步。
4. 不扩展风险标记与额外卡片字段。

## 验收标准

- 页面不出现独立数据统计区、问候语、头像或无业务价值的副标题。
- 视口宽度变化时，卡片按可用空间平滑换列，不出现固定列宽溢出；卡片高度保持一致。
- 切换任一年级后，仅展示该年级学生；选择“全部”恢复全部学生。
- 每张卡片按未完成、已完成分组；每组最多渲染 3 条任务，已完成任务有复选框选中态与删除线。
- 每张卡片在年级旁展示来自合同的一个或多个科目文字，多个科目用顿号分隔；不展示班级信息。
- 当任一任务组超过 3 条时，组末显示准确的剩余任务数量。
- 点击复选框提交期间禁用该项；成功后刷新真实分组与计数，失败保留确认状态并提示，刷新后持久化一致。
- 点击“查看详情”进入对应学生详情路径；无数据时展示空状态。
- 快捷操作仅给轻量提示，不发起范围外写请求。

## S6 本轮确认（取代原型数据与待确认口径）

只展示在读学生卡片，顶部activeStudents为全部在读数；grade仅筛卡片，服务端分页默认20最大100。GET /api/home/list仅page/pageSize/grade，返回Page<HomeStudent>加activeStudents/asOfDate（Asia/Shanghai当天）。卡片显式id/name/grade/school/status、真实subjects/expiryDate/expiresInDays/plans、pendingTasks/completedTasks（各<=3）、pendingCount/completedCount和pendingRemaining/completedRemaining。没有监护人信息。

合同聚合复用有效合同规则，0<=expiresInDays<=7显示到期提示；计划为真实{id,title}。任务摘要JOIN当前定义显示标题/科目/说明，不保存快照；完成记录不标逾期。未完成按dueDate/id升序，完成按completedAt/id降序，准确总数不来自摘要长度。

保留响应式卡片、年级联动和既有快捷操作提示，不扩展学生新增或风险标记。任务复选框调用统一completion接口，提交禁用、失败保持确认状态并提示、成功刷新分组和计数；跨页/窗口聚焦重读。loading/empty/error明确且无mock回退。最多三条/剩余数由服务端返回；无任务显示暂无任务。

验收：仅在读、筛年级不改顶部数、正常分页、准确两组计数/剩余数、7天合同提示、真实计划、三处状态一致、失败恢复、同版本冲突、响应式布局。数据边界仅S6写分配，S1–S5不变。

## S12 学生动态卡片（已实现，待验收）

S12 以“接下来要做什么”和“最近发生了什么”替代首页卡片原有的未完成 / 已完成任务双分组。学生卡片仍是首页主体，仍只展示当前权限范围内的在读学生；不新增独立数据区、风险、提醒或新页面（卡片悬浮任务列表与快速添加学习记录见 2026-09-26 章节）。

### 卡片信息结构

保留姓名、7天内到期标签、年级与科目、学习计划标签和学生标签。移除卡片头部的 `已完成数 / 总任务数` 比值及原“已完成”任务组；班级继续不展示。

卡片主体固定为以下两个区域：

1. **待办任务**：仅展示 `pending` 任务分配，按截止日期升序、ID 升序，最多 3 条；每条显示任务名称和紧凑的截止日期。逾期任务依现有规则优先反映在日期样式中。超过 3 条时显示准确的“+N 项待办”，不再展示完成任务。
2. **最新动态**：混合展示最近活动，按活动发生时间倒序，最多 5 条。活动仅有两类：
   - `完成了「任务名称」`：来源为任务分配从待完成变为已完成的 `completed_at`；
   - `添加学习记录：缺 / 补 / 强 · 内容摘要`：来源为学习记录的首次 `created_at`，摘要最多 48 个 Unicode 字符。

学习记录的编辑、任务定义编辑、合同或计划变化均不生成动态。活动发生时间统一以服务端 UTC 返回、前端按 Asia/Shanghai 格式化；同一时间按来源 ID 倒序，保证稳定排序。

待办任务可以继续使用复选框完成。勾选成功后该任务从待办区消失，并在刷新后的“最新动态”中出现“完成了…”；提交中仅禁用当前复选框，失败不伪造完成或动态。

### 卡片跳转与无障碍

整张学生卡片（除可交互的复选框、计划标签链接和标签自身操作外）点击进入 `/students/:id`。键盘焦点进入卡片后，Enter 与 Space 同样跳转；嵌套交互控件必须阻止卡片跳转，不能出现一次点击同时完成任务又跳详情。移除重复的右下角“查看详情”链接，以释放内容空间；卡片需保留清晰的悬停和焦点样式说明可进入详情。

无待办时显示“暂无进行中任务”；无动态时显示“暂无最新动态”。两个空状态彼此独立，不把加载失败伪装为空。卡片保持固定高度，动态每行单行省略，内容超过卡片可视容量时以本节的任务上限 / 动态上限控制，不允许溢出。

### 数据契约与查询边界

`GET /api/home/list` 保持原分页、年级、学生标签筛选和权限范围，不增加新接口或迁移。`HomeStudent` 取代 `completedTasks/completedCount/completedRemaining`，增加：

```ts
activities: Array<{
  id: string; // activity:<sourceType>:<sourceId>
  type: "task_completed" | "learning_record_created";
  occurredAt: string; // UTC ISO 8601
  taskTitle?: string;
  category?: "缺" | "补" | "强";
  recordSummary?: string; // 最多48个Unicode字符
}>; // 最多5条
```

保留 `pendingTasks`（最多3条）、`pendingCount` 与 `pendingRemaining`。API 必须先分页和权限过滤学生，再针对该页学生批量查询任务与动态；不得逐卡查询。动态使用任务完成时间和学习记录创建时间的参数化 `UNION ALL` / 窗口分组查询，按学生取前5条。DTO 不返回监护人信息、学习记录全文、任务说明、操作人或任何未在卡片使用的字段。

实现对应：`HomeStudentCard.vue` 负责卡片、跳转与键盘隔离；`useHome.ts` 完成成功后完整 refresh；`server/api/home/list.get.ts` 从会话取身份，`server/db/home.ts` 在分页前限制 admin 全部在读、advisor 自己负责的在读学生，顶部在读人数使用相同权限范围；`server/db/home-activities.ts` 批量读取待办和动态。类型在 `types/api/home.ts`。时间和来源 ID 完全相同时，以来源类型作为最后稳定排序键。学习记录编辑仅可能更新已有动态的摘要文本，不增加动态或改变发生时间；恢复待办后不再展示该条完成动态。

卡片固定 510px；任务和动态各自限制数量，摘要单行省略。计划/学生标签过多时标签区可纵向滚动，保留全部标签可访问；筛选操作栏在窄屏换行，年级快捷项横向滚动。验证记录见 [S12 验收记录](../test/home-student-activity-card-acceptance.md)。

### S12 验收标准

- 每张卡片只显示最多3项待办与最多5条动态；待办按截止日期排序，动态按时间倒序且稳定。
- 已完成任务不再以任务清单显示；完成成功后在对应学生动态区出现一次完成活动。
- 新建学习记录后，正确显示分类和截断摘要；编辑旧记录不增加新动态。
- 无任务、无动态、加载中、加载失败分别有正确且互不干扰的表现。
- 点击卡片空白区域、使用Enter/Space可进入详情；点击复选框或计划链接不触发卡片跳转。
- 年级、标签、分页及权限过滤下的在读数和学生范围保持现有口径；不新增数据库表、迁移、后台任务或 mock 回退。

## 2026-09-14：负责学科默认筛选（已实现）

每个登录账号都是学管师；`admin` 只是额外的账号与数据管理权限，不是另一种人员身份。每位学管师可维护 0–10 个“负责学科”，并以此作为工作台的默认学生视图，不写死“英语”。

- 首页新增科目多选筛选。初次进入或点击“恢复我的负责科目”时使用当前登录人的负责学科；例如只负责英语时，仅展示当前有效合同科目包含“英语”的学生。
- 多个负责/手动选择的科目使用“任一命中”（OR）关系；与年级、学生标签和现有数据权限范围使用“同时满足”（AND）关系。
- 清空科目选择等同“全部科目”，展示当前账号本来就有权查看的全部在读学生；不会因此扩大数据权限。
- 没有配置负责学科时，默认筛选结果为空，并提示“尚未配置负责学科”，提供进入个人设置的入口；不静默回退为英语或全部科目。
- “我的学生”旁的在读数量继续代表当前权限范围内的全部在读学生，不因年级、标签或科目筛选变化；筛选后的卡片总数、分页和空状态按组合条件计算。
- 科目匹配复用学生卡片的有效合同聚合口径：时间合同为“生效中”、课时合同为“进行中”的合同科目；过期、已结课或未生效合同不命中。学生有多个有效合同科目时只要任一科目命中即可。
- 负责学科不是学生负责人、学生归属或合同编辑权限的替代，也不改变首页已有 admin 全量 / advisor 本人学生的数据权限 SQL 范围。

实现对应：`useHome.ts` 管理 `responsible / selected / all` 三种模式及分页复位；`GET /api/home/list` 在既有权限、在读、年级和标签条件后追加参数化有效合同 `EXISTS`；Header 个人设置复用 `SubjectMultiSelect.vue`。无配置时服务端显式返回 `subjectConfigurationRequired: true`，页面提供个人设置与“查看全部科目”入口。

## 2026-09-26：卡片悬浮任务列表与快速添加学习记录（已实现）

在不改变卡片高度、分页和权限范围的前提下，为每张学生卡片补充两个高频操作：

- **悬浮查看全部任务**：鼠标悬浮在卡片“待办任务”区域，或点击该区域的“全部任务”按钮，弹出浮层展示该学生全部任务分配，按“待办任务”和“已完成任务”两组分区；浮层可纵向滚动，已完成为删除线，待办逾期保持红色日期。浮层内容按需请求 `GET /api/task-assignments/list?studentId=…&pageSize=100`，不扩大首页 DTO，也不逐卡预取。
- **快速添加学习记录**：卡片右上角新增“＋”按钮，点击弹出表单。分类默认“缺”、科目默认“英语”、发生日期默认 Asia/Shanghai 今天；正文必填（1–10000 字），科目可清空为“综合/通用”。保存复用 `POST /api/learning-records/create`，成功后关闭弹窗、刷新首页，并出现对应的“添加学习记录”动态。

交互约束：悬浮浮层仅展示，不改写任务状态，卡片上的待办复选框行为不变。浮层的展开按钮与“＋”按钮都必须阻止事件冒泡，点击后不能同时跳转学生详情；键盘 Enter/Space 进入详情、点击复选框或计划标签不跳转的既有规则保持不变。

实现对应：`useStudentTasks.ts` 按学生读取并拆分待办/已完成；`StudentTasksPopover.vue` 负责悬浮浮层与滚动列表；`QuickRecordDialog.vue` 负责表单与提交；`HomeStudentCard.vue` 触发 `quickRecord` 事件；`pages/index.vue` 持有弹窗状态并在保存后提示。验证记录见 [悬浮任务与快速添加验收](../test/home-card-quick-actions-acceptance.md)。
