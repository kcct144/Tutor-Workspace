## 范围与页面

仅 /plans 的读取、标题/摘要/正文搜索、正文编辑和学生只读多对多关联。保持左右布局：左侧服务端分页（默认20，最大100）、搜索、标题/摘要/更新时间，右侧按需加载详情、阅读、编辑、取消和保存。无新建/删除/复制/导入导出/关系管理/协作/历史版本/权限。关系表每一行仅表示进行中的关联，由显式合成种子维护。

首次选中首份文档；学生标签可链接 /plans?planId=真实ID，独立加载目标详情，不要求该文档在当前列表页。搜索或翻页只更新左侧，保留右侧选择和草稿；点击不同文档时若存在未保存修改须确认，取消则维持原选择。快速切换取消旧请求，旧响应不可覆盖新文档。离开页面或关闭窗口有未保存内容时提示；保存过程中禁止切换、取消与重复提交。

## 接口契约

| 方法与路由                    | 输入                                 | 输出                                      |
| ----------------------------- | ------------------------------------ | ----------------------------------------- |
| GET /api/study-plans/list     | page/pageSize、keyword（最多64字符） | {items,total,page,pageSize}；列表不带正文 |
| GET /api/study-plans/detail   | id                                   | 含原始Markdown正文的详情                  |
| PATCH /api/study-plans/update | 仅id、content、expectedVersion       | 更新后详情                                |

列表DTO：id、title、summary（可null）、updatedAt、version。详情另含content、createdAt、owner:{id,name}。ID十进制string，时间UTC，统一{status,msg,data}与no-store。排序updated_at DESC/id DESC。关键词对标题、摘要、正文做参数化LIKE，转义%/_等通配符；所有列表/搜索/关联查询有LIMIT，按学生页ID批量聚合，禁止N+1。

正文按trim后Unicode码点计1–100000字符，但保存完整原字符串（含首尾空白、缩进、换行），不把trim后的内容入库。JSON传输上限2MiB以覆盖转义Unicode文本，超限413。未知字段/非法分页/空或超长正文400，不存在404，旧版本409并保留草稿，存储或会话异常503。不接受owner、ownerUserId、actor、actorId、title、summary或version等写字段。服务器从当前会话取得身份，不改变原负责人；不得公网部署。

## 渲染与编辑

复用原型受控Markdown子集：标题、段落、列表、引用、粗体、行内代码、任务清单和简单表格。先转义全部用户文本，再生成固定标签，无用户属性、原始HTML、图片、可执行链接或外部资源加载。纯渲染函数移至utils，阅读组件封装唯一受控v-html入口；原文始终可在编辑器中完整看到，不增加Markdown语法。

编辑初始草稿来自已加载版本；取消不发写请求并恢复原文。保存失败维持编辑态和草稿，409后可明确确认“重载最新版本（替换草稿）”；不自动覆盖或自动重试PATCH。保存成功更新详情并重新查询列表（搜索结果可能变化）；学生标签仍由真实关系与plan.id驱动。

## 学生与首页边界

学生列表/详情只读显示{ id,title }标签，无关联时显示“—”，不按标题去重、不使用名称数组或mock。同一计划可以关联多名学生，同一学生可关联多个计划；同名不同ID计划仍是不同标签。首页尚未接入真实学生/任务聚合，因此移除计划名称mock并明确“学习计划后续接入”，不能把mock学生ID与真实计划强行绑定。S6使用同一服务端批量关联工具，不在S4新增首页API。

## 固定合成数据与验收

标准种子固定3份计划、4条关系：两份可同名的计划分别关联学生01，首份还关联学生02，第三份关联学生03；覆盖多对多、同名不同ID与无关联学生。种子仅显式执行，首次两表为空才装载；已有完整匹配的固定数据则跳过，不覆盖正文，不补齐不匹配数据。真实API及浏览器均编辑这3份中的指定文档，不创建随机测试文档。约束/事务失败用未提交数据回滚，绝不清理持久数据。

验收覆盖分页/搜索/空结果/404、原始Markdown保留、空/超长正文、特殊字符/脚本注入、取消不写、草稿保留、快速切换、版本冲突、负责人伪造/未知字段、FK/唯一关系约束、同一计划多学生、同名不同ID标签，以及学生列表/详情与数据库关联一致。完成后交付报告记录命令、结果和保留数据的回退方案。

## 2026-09-08：计划关联任务与学生完成度（已确认，S11 真实实现）

学习计划详情在保留 Markdown 正文浏览/编辑职责的前提下，新增只读的“关联任务”和“学生任务完成度”区域。该区域不编辑任务、不编辑学生计划关联、不从 Markdown 内容推导进度；数据只来自任务定义当前的计划关联和任务分配创建时保存的计划快照。

### 关联任务

- 显示当前 `tasks.study_plan_id = plan.id` 的任务定义：任务名称、科目、状态、分配人数；按任务更新时间倒序。
- 无关联定义时显示“暂无关联任务”。任务定义之后被改到其他计划，便从本区消失；这不会改变任何历史分配的统计快照。
- `/plans` 在既有左导航与详情正文布局中展示关联任务；正文、关联任务和完成度均来自同一真实详情读取，加载、空列表和失败状态明确区分。

### 学生任务完成度

- 候选学生来自该计划当前的学生关联；每行显示学生、年级、`已完成 / 总任务分配数` 和百分比。
- 统计范围是 `task_assignments.study_plan_id_snapshot = 当前计划` 的分配；不依赖任务定义现在是否仍关联该计划。
- 总数为 0 或不存在快照分配时，显示“暂无任务”，**不显示 `0%`**；存在时完成度为 `completed / (pending + completed)`，展示为四舍五入到整数的百分比。
- 完成度不自动修改计划正文、合同、学习记录或任务；完成/恢复任务分配后，`/plans` 与对应学生详情通过任务失效通知刷新统计。
- 关联学生尚无任务、计划无关联学生、任务已关联但尚未派发均是合法空状态。

### 本轮边界与验收补充

关联任务、学生完成度由真实 API 返回；loading、empty、error 和 409 冲突提示均独立可见，窄屏下左侧列表优先收起为可横滚/堆叠区域，表格仍可查看。无图表、计划协作、正文解析进度、批量建立关联或自动派发。
