## 业务定位

任务分为“任务定义”和“任务分配”两层：学管师先维护可复用的任务定义，再在独立的分配页面手动将任务分配给一个或多个学生。当前阶段不考虑任务并发控制、自动顺延或任务系列，所有分配都由学管师明确操作。任务分配页面优先服务于按截止时间处理待办。

例如“中考高频词第 1 组”到“第 40 组”可以分别建立为 40 个任务定义；需要给学生安排哪一组，由学管师手动分配哪一组，不自动生成后续任务。

## 当前确定的规则

- 任务定义不携带某个学生的完成状态。
- 任务分配是“任务 × 学生”的执行记录；一个任务可以分配给多个学生。
- 每个学生对同一任务有独立的状态、开始时间、完成时间和完成备注。
- 任务可以不分组、不排序；是否形成连续任务由任务名称和学管师的手动安排表达。
- 停用任务不允许新建分配，但历史分配保留可查。
- 原型阶段使用 mock 数据；状态更新只在当前浏览器会话内有效，不接入真实后端、数据库或 Redis。

## 首期范围

### 任务定义列表 `/tasks`

- 使用可复用数据表格展示任务定义。
- 支持按关键词、科目、任务状态筛选。
- 支持新增、编辑、启用/停用任务定义。
- 展示任务的分配人数，帮助学管师判断使用情况。
- 从任务列表进入独立的任务分配页面，可集中处理所有学生的任务分配。

### 任务分配

- 在独立页面 `/tasks/assignments` 中选择一个任务和一个或多个学生。
- 一次操作可为同一个任务创建多条学生分配记录。
- 分配记录必须填写截止时间，并按逾期、今天到期、未来到期区分时效。
- 已存在未完成分配的学生不重复创建；是否允许重复分配待确认。
- 可在分配表格的操作列直接勾选/取消勾选完成状态：勾选为“已完成”，取消勾选恢复为“待完成”。

## 当前原型实现

- `/tasks` 已实现任务定义列表、关键词搜索、科目/状态筛选、分页、新增、编辑和启用/停用。
- 任务名称单元格同时展示任务说明；列表展示分配人数和更新时间；“分配管理”直接进入独立分配页面。
- `/tasks/assignments` 已实现任务/学生关键词搜索、科目/状态/时效筛选，按截止时间优先展示逾期记录，并支持分页。
- 分配页面已实现手动选择一个任务和多个学生创建分配，以及通过操作列复选框切换单条分配的完成状态。
- 所有操作只更新当前浏览器会话中的 mock 状态，不会永久保存。

## 页面字段

### 任务定义列表

| 字段     | 说明                   |
| -------- | ---------------------- |
| 任务名称 | 可复用任务标题         |
| 科目     | 任务所属科目           |
| 任务状态 | 草稿 / 启用 / 停用     |
| 分配人数 | 任务当前关联的学生数量 |
| 更新时间 | 最近编辑时间           |
| 操作     | 编辑、查看详情、分配   |

### 任务分配记录

| 字段     | 说明                                       |
| -------- | ------------------------------------------ |
| 学生     | 被分配学生                                 |
| 任务状态 | 待完成 / 进行中 / 已完成 / 已跳过 / 已取消 |
| 截止时间 | 该学生这条任务分配的处理截止时间           |
| 分配时间 | 创建分配记录的时间                         |
| 完成时间 | 学生任务完成时间                           |
| 完成备注 | 完成时补充说明                             |
| 操作     | 勾选完成或取消完成                         |

## 状态流转

```text
任务定义：草稿 ──启用──> 启用 ──停用──> 停用

任务分配：待完成 ──开始──> 进行中 ──完成──> 已完成
             └──跳过──> 已跳过
             └──取消──> 已取消

原型中的操作列复选框仅负责“已完成/待完成”之间的快速切换；“进行中、已跳过、已取消”保留为状态模型，后续如需操作入口待确认。
```

状态只作用于单条学生分配记录，不影响任务定义本身，也不影响同一任务分配给其他学生的记录。

## 明确不做

- 不建立任务系列表。
- 不建立学生加入系列关系。
- 不自动创建下一任务。
- 不要求任务按顺序完成。
- 不处理跨学生的并发锁或抢占机制。

## 待总指挥确认的问题

1. 同一任务是否允许重复分配给同一个学生？建议禁止存在多条未完成重复分配。
2. 任务是否需要截止日期、优先级、预计耗时、附件、验收人等字段？
3. 任务定义被编辑后，已分配给学生的任务是否同步更新，还是保存分配时的内容快照？
4. 任务分配是否支持按年级、状态、科目或合同批量筛选学生？
5. 任务完成由学生、学管师还是指定验收人操作？
6. 首页和学生详情页展示所有分配任务，还是只展示未完成和最近完成任务？

## 可测试验收标准（草案）

- 任务列表能展示任务定义，并按关键词、科目和状态筛选。
- 一个任务可分配给多个学生，任务定义列表不因学生数量重复。
- 一次分配操作可选择多个学生，并生成对应的分配记录。
- `/tasks/assignments` 独立展示分配记录，并支持按截止时间识别逾期和今天到期任务。
- 每个学生的任务状态独立变更，不影响其他学生；操作列复选框可将任务标记为已完成或恢复为待完成。
- 新建分配时必须选择任务、至少一名学生和截止时间；存在未完成重复分配时阻止创建。
- 停用任务不允许新分配，历史分配仍可查询。
- 页面所有变更明确标注为原型数据，仅在当前浏览器会话内有效。
