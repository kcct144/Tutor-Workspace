## 4. 数据完整性、迁移与查询审查

### 4.1 迁移及约束

- 当前批准库只有 9 张已知表（8 张业务 / 关联表及迁移台账）；000–006 共 7 条记录，逐版 SHA-256 与当前 SQL 文件匹配。
- 实际元数据汇总：9 个主键、2 个非主键唯一约束、13 个外键、22 个 CHECK、0 个触发器。13 个外键的 ON DELETE / ON UPDATE 均为 RESTRICT。
- 000 为台账；001 为 users / students；002 合同 UUID 唯一、日期 / 课时互斥与非空组合；003 记录分类、正文、版本；004 文档及复合主键关系；005 任务两态；006 分配两态、完成时间一致性和待完成唯一。
- 006 的 `pending_marker` 为 STORED GENERATED，待完成取1、完成取NULL；唯一键为 `(task_id, student_id, pending_marker)`。当前没有重复待完成，历史完成时间按等价格式核对一致；完成 / 恢复状态约束经真实固定事务验证。
- 外键 / 筛选 / 排序相关索引存在，包含学生日期、最近跟进、计划反向关系、任务状态、分配学生与完成 / 截止日期索引；唯一键前缀支持 task_id / student_id 检索。没有对大数据量执行计划、延迟、锁等待进行压测。
- 迁移 manifest 显式顺序执行；已登记且校验和一致则跳过，不一致或未登记同名表则停止；有执行锁，DDL 非整体事务，无自动破坏性 down。**本轮只静态审查重复执行逻辑与读取台账，未实际执行迁移或种子。**
- 种子均显式入口，无 dev / build / postinstall 自动装载。S1 / S2 / S3 采取非空或已有数据跳过，不能把“跳过”理解为完整数据校验；S4–S6 有固定集合核对。旧 S2 接口脚本使用随机后缀并保留合同，明确不满足本轮可重复固定样例要求，未执行。

### 4.2 一致性与并发

- 分页业务列表均有 LIMIT；COUNT / MAX 聚合单行输出不按“无界返回列表”处理。关键词经过 LIKE 通配符转义，用户值参数绑定，动态表名 / 字段 / 排序均为代码中的固定选项。
- 合同有效谓词共用服务端上海日期；学生按当前页 ID 聚合有效科目、MIN有效时间合同到期；记录按 MAX(occurred_on) 聚合，不保存冗余最近跟进；计划按学生批量 JSON 聚合，不按名称合并。
- 首页为分页学生加批量合同 / 计划 / 任务查询，非每卡查询；非空页面为6条领域查询（不含连接校验 / 事务控制）。任务列表的分配人数另作当页任务 ID 批量 `COUNT(DISTINCT student_id)`；不是按分配次数计数。
- 首页用窗口 COUNT / ROW_NUMBER 从完整历史算组内总数和前三条，外层 LIMIT 不截断组计数；待完成按截止日 / ID，完成按完成时间 / ID。不存在“摘要数组长度冒充总数”。
- 批量分配锁任务行，确认启用、学生存在和待完成占位，再单条批量 INSERT；停用操作更新同一任务行。唯一键兜底，失败事务回滚；不自动重试 POST。
- 完成通过目标布尔值 + 版本条件 UPDATE，同版本同目标保持时间 / 版本；恢复冲突回滚，旧版本409。合同 / 记录 / 计划 / 任务更新均有版本条件；服务端配置校验不等于身份授权。
- 10 个写 API 均使用有界 JSON、服务端校验、有效 DEV_ACTOR、事务和统一响应。连接池在 finally release；事务在错误时 rollback、提交前校验；未发现忽略错误并显示 mock 成功的路径。
- Markdown 先转义文本后生成固定标签，不允许原始 HTML / 用户 URL，浏览器固定危险负载验证通过。
