# S10 出勤独立验收修复交付记录

- 日期：2026-09-08
- 范围：仅 ATT-P2-01 与 ATT-P3-01；未改写独立验收报告。

## 修复内容

`server/db/attendance.ts` 的更新路径不再先执行 `FOR SHARE` 后申请更新锁。它先以普通读取取得审计前值，再执行单条带学生、日期、时段、版本和 `status<>目标状态` 条件的原子更新。两个客户端持相同版本竞争时，其中一个更新成功，另一个条件更新为零行并通过 `FOR UPDATE` 当前读确认已过期后返回 `409 VERSION_CONFLICT`；不会把这类正常竞争交给死锁/503 处理。

创建的唯一键冲突继续映射为 409。相同版本重复提交当前状态现在是明确的无副作用成功：返回当前记录，不增加版本或维护时间，也不写审计。旧版本即使目标状态相同仍返回 409。连接、事务或真实存储失败没有被伪装为冲突，继续由统一安全 envelope 返回 503；没有自动重试。

写入和审计调用仍由 API 的既有 `inTransaction` 包裹。审计失败会抛出并触发整个事务回滚。
