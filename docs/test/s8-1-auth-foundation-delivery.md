## 2. 文件与用途

- `database/migrations/008_auth_accounts.sql`：账号表、角色/状态/版本约束、唯一用户名和人员 RESTRICT 外键。
- `database/migrations/009_auth_sessions.sql`：不透明会话摘要表、期限/撤销约束和账号 RESTRICT 外键。
- `database/migrations/010_authorization_audit.sql`：追加式审计表、人员/学生 RESTRICT 外键及学生负责人范围索引。
- `database/migrate.mjs`、`server/db/safety.ts`：把 008–010 加入固定清单，并以逐条精确 SQL 白名单、校验和和学生索引核对保护重复执行。
- `server/db/auth-rules.ts`：用户名、角色、状态、密码规则与 Node 24 原生 Argon2id PHC 哈希/校验。
- `server/db/auth-accounts.ts`、`server/db/auth-sessions.ts`、`server/db/audit.ts`：参数化账号引导、会话与脱敏审计 DAL；多表引导在同一事务内完成。
- `database/init-admin.mjs`：仅本机 TTY 的初始管理员手工引导，不接受用户名或密码命令行参数。
- `tests/unit/auth-foundation.test.ts`、`tests/integration/auth-foundation.mjs`：纯规则、迁移白名单、引导事务与真实数据库约束/回滚验证。
- `README.md`、`database/README.md`、`package.json`：命令和 S8.1 使用边界。

## 3. 迁移与实际结果

执行命令：

```powershell
pnpm db:migrate
```

执行前由连接层校验批准库；实际结果为 `008_auth_accounts`、`009_auth_sessions`、`010_authorization_audit` 均应用成功。随后重复执行同一命令，008–010 均因版本与校验和匹配而安全跳过。

迁移未创建账号、管理员、测试学生、合同、任务、记录或种子数据。DDL 无自动 down：回退应用时保留三张表、索引与可能的后续数据；若要移除结构，必须单独取得破坏性操作批准。

## 4. 初始管理员手工命令

仅在迁移完成后，由授权操作者在本机交互式终端运行：

```powershell
pnpm db:init-admin -- --apply --confirm
```

默认不带参数时只预检批准库和启用管理员数量。实际写入前，命令要求隐藏输入账号、密码和确认密码：

- `users` 为空时，同一事务创建人员与唯一启用管理员。
- `users` 非空时，只接受操作者手工输入的既有人员 ID；不显示人员列表、不猜测人员。
- 已有启用管理员、既有人员不存在或已有登录账号时停止且不写入。
- 密码不进入命令参数、日志、`.env`、Git 或错误对象。

本次只执行了无写预检，确认人员表为空且命令未创建管理员；没有执行 `--apply --confirm`。

连接、批准库、迁移、权限、事务、数据库驱动和其他未知异常仍由原有通用安全提示处理；不输出密码、哈希、连接配置、堆栈或驱动详情。该修复没有运行 `--apply --confirm`，没有创建账号或修改任何数据库数据。
