# 登录验证与权限管理验收方案（S8 MVP）

- 状态：已确认
- 负责人：测试负责人（产品与技术设计提供验收基线）
- 创建日期：2026-09-07
- 最后更新日期：2026-09-07
- 关联需求：S8 登录验证、账号管理、学生权限隔离、操作审计

## 1. 验收目标

验证 S8 能在不依赖 `DEV_ACTOR_ID`、JWT 或 Redis 的情况下完成真实登录，并保证管理员全局权限、学管师学生归属权限、会话撤销和关键写操作审计均由服务端可靠执行。前端隐藏菜单不能作为通过权限验收的唯一证据。

本文件是已确认的验收基线，不代表已经创建测试账号、迁移数据库或执行测试。

## 2. 验收环境与数据

### 2.1 环境要求

- 仅在总指挥批准的 `tutor_workspace` 合成环境执行。
- Nuxt 只监听 `127.0.0.1` 或 `localhost`，不得公网部署。
- 执行迁移或写入前复用数据库预检，禁止输出 `.env`、连接串、密码、Cookie 或 Token。
- 浏览器验收至少覆盖当前 Chromium 桌面视口和 375px 窄屏。
- API 验收直接调用服务端接口，不能只依赖页面按钮是否可见。

### 2.2 固定角色与归属样例

实施时准备固定、可重复识别的合成账号和学生，不使用真实个人信息：

| 标识 | 角色/归属            | 用途                     |
| ---- | -------------------- | ------------------------ |
| A0   | 管理员，启用         | 全局权限、账号管理、审计 |
| A1   | 学管师甲，启用       | 甲名下学生和任务定义     |
| A2   | 学管师乙，启用       | 乙名下学生和任务定义     |
| A3   | 学管师，停用         | 停用登录与会话撤销       |
| S-A  | owner=A1             | 学管师甲正常数据         |
| S-B  | owner=A2             | 越权隔离数据             |
| S-U  | owner=null，待分配   | 未分配池及并发认领       |
| S-X  | owner=null，非待分配 | 管理员处理的异常归属边界 |

S-A、S-B 分别关联至少一份合同、学习记录和任务分配；测试任务包含 A1 owner、A2 owner 和管理员 owner 的启用/停用定义。测试数据数量和装载方式由开发交付文档锁定，重复执行必须复用，不随机累计。

| ------- | -------------- | ------------------------------------------------------------------------------------ | ---------------------------------------------------------- |

| DB-04   | 既有引用       | 比较迁移前后 users、students、contracts、records、plans、tasks、assignments 外键字段 | 既有 ID 和引用值不变；未自动开账号或改派学生               |
| DB-05   | 账号约束       | 尝试重复 username、非法 role/status、无 users 的 account                             | 数据库或服务端拒绝，事务无残留                             |
| DB-06   | 会话约束       | 重复 token_hash、期限关系非法、无账号 user_id                                        | 拒绝写入                                                   |
| DB-07   | 审计约束       | 无 actor、无目标用户/学生引用                                                        | 拒绝写入；业务事务同时回滚                                 |
| BOOT-01 | 首次建立管理员 | 通过本机隐藏输入执行引导                                                             | 创建/绑定 users 与唯一启用管理员，密码不出现在命令行和日志 |
| BOOT-02 | 重复引导       | 已有启用管理员时再次执行                                                             | 明确拒绝，不新增或覆盖账号                                 |
| BOOT-03 | DEV_ACTOR 隔离 | 配置不同 `DEV_ACTOR_ID` 后执行登录/业务 API                                          | 登录身份和审计 actor 只取会话，DEV_ACTOR 不产生授权        |

数据库验收只允许事务内临时约束数据回滚或固定合成样例；不得为测试删除现有业务数据。

## 4. 登录、密码与账号验收

| 编号    | 场景                    | 预期                                                        |
| ------- | ----------------------- | ----------------------------------------------------------- |
| AUTH-01 | 启用账号 + 正确密码登录 | 200，返回最小 CurrentUser，设置会话和 CSRF Cookie，进入首页 |
| AUTH-02 | 错误密码                | 401 `INVALID_CREDENTIALS`，不创建会话                       |
| AUTH-03 | 不存在账号              | 与 AUTH-02 相同 HTTP、code 和用户文案，不提示账号不存在     |
| AUTH-04 | 停用账号登录            | 与 AUTH-02 相同公开响应，不泄露停用状态                     |
| AUTH-05 | 用户名大小写            | 服务端按小写规范化后登录，同一规范化账号不能重复创建        |
| AUTH-06 | 失败锁定                | 15 分钟内连续 5 次失败后继续尝试                            | 统一登录失败；锁定 15 分钟；响应不显示剩余次数                   |
| AUTH-07 | 锁定后恢复              | 服务端锁定时间到期后使用正确密码                            | 登录成功并清零失败计数                                           |
| AUTH-08 | 首次临时密码            | 管理员新建账号后登录                                        | 只能访问 me、改密和退出；其他接口 403 `PASSWORD_CHANGE_REQUIRED` |
| PWD-01  | 密码边界                | 测试 14、15、128、129 字符和 512 字节边界                   | 15–128 且不超字节上限成功，其余 400                              |
| PWD-02  | Unicode/空格/粘贴       | 使用含空格与 Unicode 的合法密码                             | 原样校验，不 trim、不截断，不强制组合规则                        |
| PWD-03  | 弱密码/同用户名         | 设置高频弱密码或与用户名相同                                | 400，账号原密码仍有效                                            |
| PWD-04  | 本人改密                | 当前密码正确                                                | 新密码生效，其他会话撤销，当前会话轮换                           |
| PWD-05  | 当前密码错误            | 修改本人密码                                                | 400/401 安全错误，密码与会话不变，不泄露校验细节                 |
| PWD-06  | 管理员重置              | 管理员重置 A1                                               | 只显示一次临时密码，撤销 A1 全部会话，要求下次改密               |
| PWD-07  | 存储检查                | 只读检查账号行与日志                                        | 仅有 Argon2id PHC hash，不存在明文、可逆密文或会话 Token         |
| ACCT-01 | 管理员创建账号          | 新建 users + account 或为既有 users 开通                    | 单事务成功，返回一次性临时密码并写审计                           |
| ACCT-02 | 学管师管理账号          | A1 调用任一 `/api/admin/accounts/*`                         | 403 `FORBIDDEN`                                                  |
| ACCT-03 | 停用账号                | A0 停用已登录 A1                                            | 状态成功，A1 现有会话下一次请求即 401                            |
| ACCT-04 | 角色变化                | A0 把 A1 角色改为管理员/再改回                              | 版本递增、会话撤销，重新登录后权限生效                           |
| ACCT-05 | 最后管理员保护          | 停用或降级唯一启用管理员                                    | 409，账号不变，系统仍保留启用管理员                              |
| ACCT-06 | 账号并发                | 两窗口使用同一 version 更新账号                             | 一个成功，一个 409 `VERSION_CONFLICT`                            |

## 5. 会话、Cookie 与 CSRF 验收

| 编号   | 场景           | 预期                                                 |
| ------ | -------------- | ---------------------------------------------------- |
| SES-01 | Cookie 属性    | 检查登录响应和浏览器存储                             | session 为 HttpOnly、SameSite=Strict、Path=/、无 Domain；HTTPS 时 Secure + `__Host-` |
| SES-02 | 前端读取会话   | 在页面脚本尝试读取 session Cookie                    | 读取不到；localStorage/sessionStorage 无身份 Token                                   |
| SES-03 | 未登录访问 API | 调用除 login/health 外的 API                         | 401 `UNAUTHENTICATED`，统一 envelope                                                 |
| SES-04 | 未登录访问页面 | 直接进入 `/students`                                 | 跳转登录并保存安全的站内 redirect                                                    |
| SES-05 | 恶意 redirect  | 登录参数使用外域、协议相对或脚本 URL                 | 忽略并进入首页，不开放重定向                                                         |
| SES-06 | 退出           | POST logout 后再次调用 me/业务 API                   | Cookie 清除，会话撤销，后续 401；浏览器后退不恢复数据                                |
| SES-07 | 空闲过期       | 服务端模拟超过 8 小时未活动                          | 401 并清 Cookie                                                                      |
| SES-08 | 绝对过期       | 模拟超过 7 天，即使持续活动                          | 401 并清 Cookie                                                                      |
| SES-09 | 未签发 Token   | 自造格式正确的随机 Cookie                            | 401，不建立宽松会话                                                                  |
| SES-10 | CSRF 缺失/错误 | 有会话但写请求无 header、header 不匹配或 Origin 不同 | 403 `CSRF_INVALID`，业务和审计均不写                                                 |
| SES-11 | GET 请求       | 正常读取受保护 GET                                   | 不要求 CSRF，但仍要求会话和数据权限                                                  |
| SES-12 | 停用/重置竞争  | 中间件通过后、事务写入前账号被停用                   | 写事务重新校验并拒绝，不产生业务写入                                                 |

## 9. 前端与可用性验收

- 登录页键盘可完成账号、密码和提交；允许密码管理器和粘贴。
- 提交期间禁用，重复点击只产生一个登录请求。
- Header 正确显示当前姓名/角色并可退出；不显示用户 ID 或权限调试值。
- 管理员可见账号与审计导航；学管师不可见，直接访问仍由服务端 403。
- 临时密码只在创建/重置成功后显示一次；关闭弹窗后不能从页面状态、缓存或日志恢复。
- 401 自动回到登录页；403 保留登录态并展示无权限；404 使用对应业务空状态。
- 会话失效发生在编辑期间时，页面不显示保存成功；能保留的草稿只保留在内存且不包含密码。
- 375px 下登录表单、账号管理侧栏、负责人选择、审计详情和错误提示无横向溢出，主要按钮可见。
- 登录前后的 API 响应均不回退 mock；数据库异常显示 503，不显示空数据冒充成功。

## 10. 数据工具与回归验收

| 编号   | 场景               | 预期                                               |
| ------ | ------------------ | -------------------------------------------------- |
| CLI-01 | 首次数据脚本登录   | 受控本机 TTY 隐藏读取密码并登录                    | 会话 Cookie/CSRF 只保存在工作区外、Git 忽略且仅当前系统用户可访问的本地安全目录；密码不保存、不输出      |

## 11. 通过标准与停止条件

验收通过必须同时满足：

1. AUTH、SES、RBAC、CON、REC、PLAN、TASK、ASN 和 AUD 的正常、异常、越权场景均通过。
2. 两个学管师账号可以证明 SQL 查询结果、total、聚合和直接对象访问均隔离，而不只是页面隐藏。
3. 停用、角色变更、密码重置和学生改派在下一请求生效。
4. 审计和业务事务一致，敏感信息扫描无泄露。
5. 原有业务回归通过，数据库外键与历史人员引用不变。
6. 实际执行记录列出 PASS/FAIL/SKIP；不得用单元测试替代全部真实 API 和浏览器验收。

遇到以下情况立即停止，不以临时旁路继续：

- 目标库不是 `tutor_workspace`、初始管理员不明确或发现真实个人数据。
- 权限测试能读到其他学管师的学生、联系方式、记录正文或聚合数量。
- 需要恢复 `DEV_ACTOR_ID`、匿名 API、共享管理员密码或直接 SQL 才能继续。
- 迁移部分失败、审计无法与业务同事务、最后管理员保护失效。

## 12. 已确认裁决覆盖

1. 学管师允许新增学生，服务端固定新学生负责人为当前学管师；管理员新增保持未分配。验收以 RBAC-05、RBAC-06 和 RBAC-06a 验证负责人、默认状态与请求字段隔离。
2. 启用任务定义全员可见，管理员维护全部、学管师维护本人定义，并可向本人学生派发任意启用定义；验收以 TASK-01 至 TASK-07 验证共享、维护边界与最新定义历史展示。
3. 数据工具使用受控本机首次登录后的短期会话复用；验收以 CLI-01 至 CLI-06 验证本地安全存储、失效清理、禁止持久/无头凭据与同一权限边界。
