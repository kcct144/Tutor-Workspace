# S8.2 登录闭环、会话、CSRF 与全局 API 鉴权交付记录

- 状态：已实现，等待受控本机管理员手工验收
- 完成日期：2026-09-07
- 范围：登录、当前用户、退出、CSRF 轮换、全局 API 会话边界与最小前端闭环

## 1. 实现范围

- 新增 `POST /api/auth/login`、`GET /api/auth/me`、`POST /api/auth/logout`、`GET /api/auth/csrf`；全部使用既有 `{status,msg,data}` 和 `Cache-Control: no-store`。
- 会话使用 S8.1 的 `auth_sessions`。数据库只存随机会话值和 CSRF 值的 SHA-256 摘要；空闲期限为 8 小时、绝对期限为 7 天。登录时，账号成功状态更新与会话插入在同一事务内提交。
- `tws_session` Cookie 为 HttpOnly、SameSite=Strict、Path=/、无 Domain；`tws_csrf` 仅用于同源 header 校验，不写入 localStorage/sessionStorage。仅严格回环 HTTP 开发环境使用 `Secure=false`。
- 全局 `server/middleware/auth.ts` 只放行登录和健康检查。其余 `/api/**` 先验证本机回环来源、会话摘要、会话期限和账号启用状态；缺失、伪造、撤销或过期会话统一返回 `401 UNAUTHENTICATED` 并清 Cookie。写请求再要求精确同源 Origin 与会话绑定 CSRF 值，否则 `403 CSRF_INVALID`。
- 现有学生、合同、学习记录、学习计划、任务定义和任务分配的全部写入口使用服务器请求上下文中的当前会话用户，并在原有写事务中重新检查账号启用状态。未增加负责人范围控制；该项保留给后续已确认切片。
- 新增 `/login`、全局站内路由守卫、401 前端状态清除、Header 当前用户名/角色及退出入口。跳转目标只接受单个以 `/` 开头、非 `//` 的站内路径。

## 2. 已关闭的匿名路径

`GET /api/health` 与 `POST /api/auth/login` 是仅有的公开入口。`GET /api/auth/me`、CSRF 轮换、退出、所有已有业务读取及写入均需有效会话。

## 4. 管理员手工验证步骤

1. 在仅回环地址启动服务后，浏览器打开 `/login`，由管理员自行输入凭据。
2. 成功后刷新页面，确认 Header 显示用户名和角色而不显示内部 ID；访问任一业务页可读取数据。
3. 在浏览器开发者工具确认会话 Cookie 不可由页面脚本读取，且无 localStorage/sessionStorage 身份 Token；不要复制 Cookie 或 CSRF 值到任何聊天、日志或文件。
4. 对任一允许的写操作，分别移除或篡改 `X-CSRF-Token`，以及使用不同 Origin，确认均为 `403 CSRF_INVALID` 且无业务写入；恢复正常页面后再验证一次合法写入。
5. 点击退出，确认 `/api/auth/me` 与业务 API 返回 401，浏览器后退不会恢复受保护数据。

## 5. 数据、迁移与回退

本切片没有新增或执行迁移、种子、学生、合同、记录、计划、任务或分配写入；不读取或修改 `.env`。S8.1 的 008–010 已有表继续保留。

回退仅撤回 S8.2 应用与前端接入代码；保留已存在的 `auth_sessions` 行和数据库结构，不提供自动删表、清库或 Token 导出。回退到旧匿名 API 不属于安全回退，必须另行确认。

## 6. 已知限制

- S8.2 仅提供初始管理员已存在前提下的登录闭环；不提供账号管理、改密、停用/角色变更页面，相关“全会话撤销”写入口在后续切片实现。
- 过期会话在请求时拒绝；批量清理任务不在本切片。
- 旧数据操作脚本刻意不可用，直到 S8.7 以工作区外、当前系统用户可访问的本机短期会话存储接入，不提供任何临时旁路。
